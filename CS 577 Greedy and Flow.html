Greedy algorithms

A greedy algorithm builds its answer one piece at a time. At every step it grabs whatever looks best right now, and it never goes back to change a choice.

1The idea2When it breaks3Meeting room rules4Induction5Stays ahead6Exchange7Counterexamples8The recipe

The idea: grab the best thing right now

A cashier gives you 68¢ in change. The greedy rule: always hand over the biggest coin that still fits.

68¢ with US coins, biggest first
2525105111
68 → 43 → 18 → 8 → 3 → 2 → 1 → 0. Seven coins, and that's the fewest possible with US coins.

Fast

One quick decision per step. Usually just a sort, then one pass: O(n log n).

Simple

Easy to describe in one sentence: "always take the ___".

Often wrong

Many greedy rules sound smart and still give a bad answer. That's why you have to prove the rule works.

When greedy breaks

Same rule, different coins. Suppose the only coins are 1¢, 3¢, and 4¢, and you owe 6¢.

2 coins. Greedy lost.
Lesson

A greedy rule is guilty until proven innocent. You either prove it always works, or you find a small input where it fails (a counterexample).

The meeting room: four greedy rules

One room, many meeting requests. Each request has a start and an end. Goal: fit in as many meetings as possible with no overlaps. A meeting can start the moment another ends. Pick a rule to see what it does.

Three rules fail on some input. Earliest finish is the one that always works. The R1 tab proves it.

Induction in five minutes

Greedy proofs are induction proofs in disguise, so learn induction first. Picture a long row of dominoes.

Base case

Knock over the first domino. In math: show the claim is true for the first value, P(1).

Inductive step

Show that any domino that falls knocks over the next one. In math: assume P(k) is true, then show P(k+1) is true.

If both are true, every domino falls. You never check them one by one.

Induction template
Claim
For every n ≥ 1, P(n) is true. (Write out exactly what P(n) says.)
Base
Check P(1) directly.
Assume
P(k) is true for some k ≥ 1. This is the inductive hypothesis.
Show
P(k+1) is true. Somewhere in this step you must use the assumption.
Done
By induction, P(n) holds for all n ≥ 1.

Worked example: adding odd numbers

Claim: 1 + 3 + 5 + … + (2n − 1) = n². Press Next to grow the square. Each new odd number is an L-shaped layer.

The proof, written out
  1. P(n): 1 + 3 + … + (2n − 1) = n².
  2. Base: n = 1. The left side is 1 and the right side is 1² = 1. True.
  3. Assume P(k): 1 + 3 + … + (2k − 1) = k².
  4. Show P(k+1): the left side is (1 + 3 + … + (2k − 1)) + (2k + 1). By the assumption that is k² + 2k + 1 = (k + 1)². True.
  5. By induction, the claim holds for every n ≥ 1.

In greedy proofs, n becomes "the step number of the algorithm", and P(r) becomes "after r steps, greedy is not behind".

Proof style 1: greedy stays ahead

Line up greedy's choices next to the choices of a best solution, in order. Show that after every step, greedy is at least as far along. If greedy is never behind, it can't finish with less.

Meeting room example: greedy's r-th meeting always ends no later than the best solution's r-th meeting. Ending earlier = more room left = "ahead".

Stays-ahead template
Name
Greedy picks g₁, g₂, …, gₖ. A best solution picks o₁, o₂, …, oₘ, in the same order.
Measure
Choose a number that says how far along you are (finish time, distance covered).
Induct
Prove by induction on r: after step r, greedy's measure is at least as good as the best solution's.
Finish
Use "greedy is ahead at the last step" to show k ≥ m. So greedy is optimal.

Proof style 2: the exchange argument

Start with any best solution. Wherever it disagrees with greedy, swap two pieces to make it look more like greedy, and show the swap doesn't make it worse. Keep swapping until it is greedy's answer.

Before: two neighbors in the "wrong" order
After the swap: no worse

Jobs with deadlines (the flags). Job j has the earlier deadline but runs second. Swapping them lowers the worst lateness from 3 to 1. The R3 tab proves a swap like this never hurts.

You pick items one at a time and can measure progress (meetings, towers, gas stops).The answer is an order or an arrangement (scheduling jobs, sorting by a rule).

Killing a bad rule with a counterexample

  • Use tiny inputs: 2 to 4 items. Draw them.
  • Make the rule's favorite choice block several other good choices (one long meeting, one big coin).
  • Show both answers side by side: what the rule does, and something better.
  • One counterexample is a complete proof that a rule is wrong.

Network flow and Ford-Fulkerson

Think of one-way water pipes. Each pipe can carry only so much per second. How much water can you push from the source to the sink at the same time?

1Pipes2Two rules3First try4Residual graph5Backward edges6Ford-Fulkerson7Min cut8Integers and time9Modeling recipe

A flow network is a set of pipes

Source s and sink t

Water enters at s and leaves at t. Every other vertex is just a junction.

Capacity c(e)

The most an edge can carry. Written after the slash: 7/10 means 7 flowing, capacity 10.

Flow f(e)

How much actually flows on each edge. The moving dashes show edges in use; thick dark ones are full.

This is the max flow for this network, which Ford-Fulkerson finds further down. Its value is 19.

The two rules every flow must follow

1. Capacity rule

0 ≤ f(e) ≤ c(e). A pipe can't carry more than it holds, and flow can't be negative.

2. Conservation rule

At every vertex except s and t, flow in = flow out. Here 3 + 2 in, 4 + 1 out. Nothing leaks, nothing appears.

Value of a flow

v(f) = total flow leaving s (which equals the total arriving at t). The max flow problem: find a flow with the largest value.

First try: push along any path with room

A natural idea: find a path from s to t where every edge has room, push as much as fits, repeat. Watch what happens if the first path is unlucky. Left: the flow. Right: the residual graph, explained in the next section.

Stuck

The best answer is 2 (s → a → t and s → b → t), but this version is stuck at 1. Choosing a bad path early can't be fixed by only adding flow. You also need a way to take flow back.

The residual graph: room left and flow you can undo

For every edge u → v carrying f out of c, the residual graph G_f has up to two edges:

Forward edge u → v

Residual capacity c − f: how much more you could push. Drawn solid.

Backward edge v → u

Residual capacity f: how much you could take back (undo). Drawn dashed amber.

The edge in G
Its two residual edges in G_f

An edge with 0 residual capacity disappears from G_f. A full edge has no forward edge; an empty edge has no backward edge.

Backward edges fix the stuck example

An augmenting path is any s → t path in the residual graph. It may use backward edges. Same unlucky first path as before, but now we search the residual graph.

What the backward edge did

Pushing 1 along b → a in G_f took the flow off a → b. The water that went s → a → b now goes s → a → t, and the new path s → b → t uses the freed room. Net result: 2.

Ford-Fulkerson

Keep finding augmenting paths in the residual graph and pushing the bottleneck amount along them. Stop when s can't reach t in the residual graph. Here the path is found with BFS (the shortest path), which is the Edmonds-Karp version.

augmenting pathedge carrying flowflow being undonereachable from s at the end

Cuts and the max-flow min-cut theorem

A cut (A, B) splits the vertices into two sides: s in A, t in B. Its capacity is the total capacity of edges going from A to B. Edges going from B back to A don't count. Pick a cut:

side A (with s)side B (with t)A → B edge, countedB → A edge, not counted

Flow ≤ any cut

All water must cross from A to B somewhere, so no flow can beat any cut's capacity.

Max flow = min cut

The biggest flow equals the smallest cut. Here both are 19.

The certificate

When Ford-Fulkerson stops, A = everything s can still reach in G_f. That cut's capacity equals the flow, which proves the flow is max.

Whole numbers and running time

Integrality theorem

If every capacity is a whole number, Ford-Fulkerson only ever pushes whole numbers, so it ends with a max flow where every edge carries a whole number. This is what lets flow answer yes-or-no assignment questions (P1, P2).

VersionTimeWhy
Ford-Fulkerson, whole-number capacitiesO(F · (m + n))Each path adds at least 1, so at most F paths (F = max flow value). Each path search is one BFS or DFS.
Edmonds-Karp (always the shortest path, by BFS)O(n · m²)Doesn't depend on the capacity numbers at all.
Ford-Fulkerson, irrational capacitiesMay never stopEach push can get smaller and smaller forever. That's HW5 P4.

F can be huge compared to the input size (capacities like 1,000,000 take only 7 digits to write), so O(F · (m + n)) is not polynomial. That's why Edmonds-Karp matters.

Step 4 Pick the proof style

We pick intervals one at a time, so use greedy stays ahead. The measure: the finish time of the r-th pick. Finishing earlier means more room left, so earlier is "ahead".

Step 5 Prove it

Step through the proof on a small example. Greedy's picks are on top, a best solution's picks are below.

The proof, written out
  1. Let greedy pick g₁, …, gₖ in order. Let O be any optimal set, with intervals o₁, …, oₘ sorted by finish time. We show k = m.
  2. Claim: for every r ≤ k, f(gᵣ) ≤ f(oᵣ). Proof by induction on r.
  3. Base (r = 1): greedy's first pick ends earliest of all intervals, so f(g₁) ≤ f(o₁).
  4. Step: assume f(gᵣ₋₁) ≤ f(oᵣ₋₁). Since O has no overlaps, s(oᵣ) ≥ f(oᵣ₋₁) ≥ f(gᵣ₋₁). So oᵣ doesn't overlap greedy's first r − 1 picks, and was available when greedy chose gᵣ. Greedy chose the available interval that ends first, so f(gᵣ) ≤ f(oᵣ).
  5. Finish: suppose m > k. Then oₖ₊₁ exists and s(oₖ₊₁) ≥ f(oₖ) ≥ f(gₖ), so it was still available after greedy's last pick. But greedy only stops when nothing is available. Contradiction, so m ≤ k, and greedy is optimal.

Step 6 Running time

sort by finish time: O(n log n)
one pass, O(1) per interval: O(n)
total: O(n log n)

Minimize the maximum lateness

The problem

Jobs have processing times tⱼ and deadlines dⱼ, and run one at a time on a single machine. If job j finishes at time fⱼ, its lateness is max(0, fⱼ − dⱼ). Minimize the largest lateness. (1) Give counterexamples for "shortest job first" and "smallest slack dⱼ − tⱼ first". (2) Prove that Earliest Deadline First (EDF) is optimal with an exchange argument.

Proof style: exchange
1Understand2Try rules3Algorithm4Proof style5Prove it6Running time

Step 1 Understand the problem

Input
→
n jobs, each with a length tⱼ and a deadline dⱼ
Valid answer
→
An order to run the jobs, back to back from time 0
Better answer

Smaller worst lateness

Each flag is a deadline. A red bar under a job shows how late it finished. Only the biggest red bar matters.

Step 2 Try rules and kill the bad ones

Shortest job first: wrong

Job 1: t = 1, d = 11. Job 2: t = 10, d = 10.

Shortest first: job 1, then job 2 → worst lateness 1
EDF: job 2, then job 1 → worst lateness 0

Smallest slack first: wrong

Job 1: t = 1, d = 2 (slack 1). Job 2: t = 10, d = 10 (slack 0).

Smallest slack: job 2, then job 1 → worst lateness 9
EDF: job 1, then job 2 → worst lateness 1

The length of a job doesn't tell you how urgent it is. The deadline does. That points to earliest deadline first.

Step 3 Write the algorithm

Step 4 Pick the proof style

The answer is an order, so use the exchange argument. Key word: an inversion is a pair of jobs where the one with the later deadline runs first.

Step 5 Prove it

Start from any schedule and keep swapping two neighboring jobs that form an inversion. Watch the worst lateness: it never goes up, and you end at EDF's order.

The proof, written out
  1. No idle time: some optimal schedule has no gaps, because a gap only delays jobs. Let O be such a schedule.
  2. Neighbors: if O has an inversion, it has one between two neighboring jobs i, j (i runs right before j, but dⱼ < dᵢ). If every neighboring pair were in deadline order, the whole schedule would be sorted.
  3. The swap doesn't hurt: swap i and j. Every other job finishes at the same time as before. j now finishes earlier, so its lateness can't go up. i now finishes where j used to, at fⱼ, so its new lateness is fⱼ − dᵢ < fⱼ − dⱼ, which was j's old lateness. So the worst lateness doesn't go up.
  4. Keep going: each swap removes one inversion, so after finitely many swaps O has no inversions and is still optimal.
  5. Same as EDF: any gap-free schedule with no inversions is EDF's order, except that jobs with equal deadlines may be in a different order. Those jobs run in one block that ends at the same time, so the worst lateness is the same. So EDF is optimal.

Step 6 Running time

sort by deadline: O(n log n)
run them back to back: O(n)
total: O(n log n)

Tower right on the first uncovered house

Step 3 Write the algorithm

Step 4 Pick the proof style

Towers get placed one at a time, west to east, so use greedy stays ahead. The measure: the position of the r-th tower. Farther east means more road covered, so farther east is "ahead".

Step 5 Prove it

The proof, written out
  1. Greedy places towers g₁ < … < gₖ. Let O be any valid placement, with towers o₁ ≤ … ≤ oₘ. We show m ≥ k.
  2. Claim: for every r ≤ min(k, m), gᵣ ≥ oᵣ. Proof by induction on r.
  3. Base (r = 1): house x₁ is covered by some tower oₜ of O, so o₁ ≤ oₜ ≤ x₁ + 4 = g₁.
  4. Step: assume gᵣ₋₁ ≥ oᵣ₋₁. Greedy put gᵣ at h + 4, where h is the first house its first r − 1 towers miss, so h > gᵣ₋₁ + 4 ≥ oᵣ₋₁ + 4. Then o₁, …, oᵣ₋₁ all miss h too, so h is covered by some oₜ with t ≥ r. So oᵣ ≤ oₜ ≤ h + 4 = gᵣ.
  5. Finish: suppose m < k. Greedy placed gₖ for a house h with h > gₖ₋₁ + 4 ≥ gₘ + 4 ≥ oₘ + 4. Every tower of O is at most oₘ, so none of them reaches h. O misses a house, contradiction. So m ≥ k: greedy uses the fewest towers.

HW5 · Problem 2

Fair schedule

The problem

n people carpool for d days. On day i, a nonempty group Sᵢ goes to work, and each person in Sᵢ picks up a driving obligation of 1/|Sᵢ| that day. Person j's total obligation is Δⱼ = the sum of 1/|Sᵢ| over the days j rides. A schedule assigns at most one driver (from Sᵢ) to each day. It is fair if each person j drives at most ⌈Δⱼ⌉ times. Find a fair schedule that assigns a driver to as many days as possible.

Hint: reduce to flow. What is the max flow value?

Step 1 What flows?

One unit of flow = one day's driving job. Each day has one job. It must go to one person who rides that day. Each person can take only so many jobs (⌈Δⱼ⌉).

Step 4 Prove both directions

Schedule → flow

A fair schedule that covers k days gives a flow of value k: send 1 along s → day i → its driver → t. Each day sends at most 1, and person j receives at most ⌈Δⱼ⌉.

Flow → schedule

A whole-number flow of value k gives a fair schedule covering k days: if 1 unit goes day i → person j, then j drives day i. Each day has at most one driver, and j drives at most ⌈Δⱼ⌉ times.

So the max number of covered days equals the max flow value.

Step 5 The hint: the max flow is always d

Split each day's job evenly among its riders. This is a flow, just with fractions:

  • It's a valid flow. Day i gets 1 in and sends 1/|Sᵢ| to each of its |Sᵢ| riders, so 1 out. Person j receives exactly Δⱼ ≤ ⌈Δⱼ⌉, which fits the capacity to t.
  • Its value is d. Every s → day edge carries 1. The cut around s has capacity d, so no flow beats d. So the max flow is exactly d.
  • Now use integrality. All capacities are whole numbers, so some max flow (the one Ford-Fulkerson finds) is all whole numbers. Its value is also d, and it's a real schedule: every day gets a driver, and it's fair.

Step 6 Run it and count the time

Write-up
Build
Vertices s, t, one per day, one per person. Edges s → day i (capacity 1); day i → person j for each j ∈ Sᵢ (capacity 1); person j → t (capacity ⌈Δⱼ⌉).
Run
Ford-Fulkerson (all capacities are integers, so it returns a whole-number max flow).
Return
For each day i, the driver is the person j with flow 1 on day i → j. Every day gets a driver.
Why
Whole-number flows of value k are exactly fair schedules covering k days. Splitting each day evenly gives a fractional flow of value d, and the cut around s caps flows at d, so the max flow is d. By integrality, the whole-number max flow also has value d.
Time
V = n + d + 2 and E = d + Σ|Sᵢ| + n ≤ d + nd + n. The max flow is d, so Ford-Fulkerson does at most d augmentations of O(V + E) each: O(d · (n + d + Σ|Sᵢ|)) = O(n · d²).

How to disprove a "for every input" claim

For any b someone names, build an input where the code gets less than max / b. Since the path choice isn't specified, the claim has to hold no matter which forward paths the code picks, so one bad sequence of choices is enough.

Step 2 Test it on a small graph

The diamond from the Flow tab: with the unlucky first path s → a → b → t, the forward-only code gets 1, but the max flow is 2. So b = 1 is already false. Can the gap get bigger?

Step 3 Guess

The trick in the diamond: one bad path used up the middle edge that every other path needed. Make a graph where one bad path uses up the middle edges of k good paths at once. Then the code gets 1 and the max is k. Since k can be anything, no constant b works.

Step 4 Build the bad family

Vertices s, t, u₁…uₖ, v₁…vₖ. Edges s → uᵢ, uᵢ → vᵢ, vᵢ → t for every i, plus vᵢ → uᵢ₊₁. Every capacity is 1.

Step 5 Prove it

The proof, written out
  1. The code can get stuck at 1. The zig-zag path s → u₁ → v₁ → u₂ → v₂ → … → uₖ → vₖ → t uses only forward edges, each with capacity 1, so the code may push 1 along it. That fills every uᵢ → vᵢ edge.
  2. The only edge leaving uᵢ is uᵢ → vᵢ. Every s → t path enters some uᵢ (all edges out of s go to u's) and must leave it through uᵢ → vᵢ, which is full. So no forward-only path is left, and the code stops with flow 1.
  3. The max flow is k. The k paths s → uᵢ → vᵢ → t share no edges, so together they carry k. The edges out of s have total capacity k, so no flow is bigger.
  4. Conclusion. The code's flow is 1 = max / k. Given any constant b, pick k > b: the code gets max / k < max / b. So no constant b works, and the friend is wrong.

Step 6 Write-up

Bad run
The forward-only code may first pick s → u₁ → v₁ → … → uₖ → vₖ → t, which fills all uᵢ → vᵢ. Every s → t path must use some uᵢ → vᵢ, so it stops with value 1.
Max
The k disjoint paths s → uᵢ → vᵢ → t give value k, and the cut around s has capacity k, so the max flow is k.
Finish
The ratio is k. For any b, choosing k > b gives flow 1 < k / b. So the claim fails.
HW5 · Problem 4

Failure of Ford-Fulkerson

The problem

With real-number capacities, Ford-Fulkerson might never stop, and its flow might approach a value far below the max. The graph: s → a, s → b, s → d, a → t, c → t, d → t all have capacity X ≥ 10; the middle edges are b → a (capacity 1), b → c (capacity 1), and d → c (capacity φ), where φ = (√5 − 1)/2. Use the paths A: s → a → b → c → t, B: s → d → c → b → a → t, C: s → b → c → d → t, which may use backward edges. Track (r₁, r₂, r₃), the residual capacities of (b, a), (b, c), (d, c) in their original directions. Parts (a) to (e) below.

Residual rules you'll use

An edge with capacity u and forward residual r carries flow u − r, so its backward residual is u − r. Pushing forward lowers r. Pushing backward raises r (it undoes flow).

used forwardused backward (undoes flow)

Part (a) The max flow is 2X + 1

A flow of value 2X + 1

X along s → a → t, X along s → d → t, and 1 along s → b → c → t.

A cut of capacity 2X + 1

A = {s, a, b}. Edges leaving A: s → d (X), a → t (X), b → c (1). The edge b → a stays inside A.

Why that proves it

Every flow is at most every cut's capacity, so no flow beats 2X + 1, and we have a flow of exactly 2X + 1. So the max flow is 2X + 1.

Part (b) The first push

Start at zero flow, so (r₁, r₂, r₃) = (1, 1, φ). The path s → b → c → t has room X, 1, X. The bottleneck is 1. After pushing 1, edge b → c is full: (r₁, r₂, r₃) = (1, 0, φ). The player below starts with this push.

Part (c) The inductive step: four pushes

Assume (r₁, r₂, r₃) = (φᵏ⁻¹, 0, φᵏ). Push along B, C, B, A. Step through k = 1 (the round right after part b), then k = 3, to see the pattern repeat.

Part (d) Add it all up

Part (b) pushes 1. Each round pushes φᵏ, φᵏ, φᵏ⁺¹, φᵏ⁺¹ for k = 1, 3, 5, …, so the amounts are 1, φ, φ, φ², φ², φ³, φ³, …

total = 1 + 2(φ + φ² + φ³ + …)
= 1 + 2 · φ / (1 − φ) (geometric series, 0 < φ < 1)
= 1 + 2 · φ / φ² = 1 + 2/φ (1 − φ = φ²)
= 1 + (1 + √5) = 2 + √5 ≈ 4.236 < 7
Why the X edges never become the bottleneck

Each path uses each capacity-X edge at most once, always forward. So the flow on any X edge is at most the total pushed so far, which is less than 7. Its residual capacity stays above X − 7 ≥ 3 > 1, bigger than every middle-edge amount. So the sequence can really continue forever, which also justifies the assumption in part (c).

Part (e) Conclude

  • It never stops. Every round leaves an augmenting path with positive room, so Ford-Fulkerson keeps going forever.
  • It gets stuck far from the answer. The flow values climb toward 2 + √5 ≈ 4.24, but the max flow is 2X + 1. X can be as large as you like, so the gap 2X + 1 − (2 + √5) can be made arbitrarily large.
  • The lesson: the "at most F augmentations" argument needs whole-number capacities, so each push adds at least 1. With irrational capacities the pushes can shrink forever.
