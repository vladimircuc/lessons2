0.2  Prep cell: load, clean, reframe, split

New scratch notebook lesson4.ipynb. This first cell is pure recap of weeks 2 and 3, run it and move on.

import pandas as pd
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score, confusion_matrix, classification_report

# load + clean (week 2)
df = pd.read_csv("atp_matches_2023.csv")
df["tourney_date"] = pd.to_datetime(df["tourney_date"], format="%Y%m%d")
df = df.dropna(subset=["surface", "winner_rank", "loser_rank"]).copy()
df["winner_ht"] = df["winner_ht"].fillna(df["winner_ht"].median())
df["loser_ht"]  = df["loser_ht"].fillna(df["loser_ht"].median())

# reframe: balanced target + symmetric features (week 3)
rng = np.random.default_rng(42)
df["winner_is_A"] = rng.random(len(df)) < 0.5
df["target"] = df["winner_is_A"].astype(int)
def a_minus_b(w, l):
    a = np.where(df["winner_is_A"], df[w], df[l])
    b = np.where(df["winner_is_A"], df[l], df[w])
    return a - b
df["rank_diff"]   = a_minus_b("winner_rank", "loser_rank")
df["points_diff"] = a_minus_b("winner_rank_points", "loser_rank_points")
df["age_diff"]    = a_minus_b("winner_age", "loser_age")
df["height_diff"] = a_minus_b("winner_ht", "loser_ht")

# drop any rows still missing a feature, then split by time
feature_cols = ["rank_diff", "points_diff", "age_diff", "height_diff"]
df = df.dropna(subset=feature_cols + ["target"])
df_sorted = df.sort_values("tourney_date")
cut = int(len(df_sorted) * 0.8)
train = df_sorted.iloc[:cut]
test  = df_sorted.iloc[cut:]
print("train:", train.shape[0], " test:", test.shape[0])

0.3  Name the four pieces every model needs

A model learns from features (the inputs) to predict a target (the answer). By convention the features are called X and the target y. We make four: training inputs and answers, and test inputs and answers.

X_train = train[feature_cols]   # inputs the model learns from
y_train = train["target"]       # answers it learns from
X_test  = test[feature_cols]    # inputs it has never seen
y_test  = test["target"]        # answers we check against

X_train.head()

The model studies X_train with y_train, then we ask it to predict on X_test and compare its guesses to the real y_test.

Model 1: Logistic Regression

Your first real machine learning model. Despite the name, it is a classifier: it predicts one of two outcomes, here "player A wins" or "player B wins".

What a model does, and the three-step pattern.

A model is a rule that maps inputs to an answer. It is not written by you, it is learned from the training data. Every scikit-learn model follows the same three steps: create it, fit it (learn from X_train and y_train), and predict with it (guess the answers for new inputs). Logistic regression learns a weight for each feature and combines them into a probability of A winning, then rounds to a 0 or 1.

Cell · create, fit, predict

model = LogisticRegression(max_iter=1000)   # create
model.fit(X_train, y_train)                 # learn from the training data
predictions = model.predict(X_test)         # predict on unseen test matches

predictions[:10]   # its guesses for the first 10 test matches (0 or 1)

max_iter=1000 just gives the solver enough steps to settle. After fit, the model has learned its weights. predict returns an array of 0s and 1s, one guess per test match.

Cell · how accurate is it?

accuracy_score(y_test, predictions)

accuracy_score compares the guesses to the real answers and returns the share it got right. Expect something around 0.65. Hold that thought, the next tab is about what that number really means.

The whole ML workflow in one breath: split the data, fit on train, predict on test, score the predictions. Every model you ever build follows this same shape.

Evaluating the model

Accuracy is one number. To really understand a model you compare it to the baseline and look at the kinds of mistakes it makes.

Always compare to the baseline. Remember the "favorite always wins" baseline from last week, around 0.65. A model is only impressive if it beats that. If your logistic regression scores 0.66 and the baseline was 0.65, the honest headline is "the model roughly matches the simple rule", which is a real and interesting finding in tennis, not a failure.

Cell · recompute the baseline on the test set

baseline_pred = (test["rank_diff"] < 0).astype(int)   # predict A wins if A ranked better
baseline_acc = accuracy_score(y_test, baseline_pred)
print("baseline:", round(baseline_acc, 3))
print("model:   ", round(accuracy_score(y_test, predictions), 3))

Printing them side by side is the honest comparison. Usually they are within a point or two of each other.

The confusion matrix: what kinds of mistakes?

Accuracy hides the details. A confusion matrix breaks the predictions into four boxes: correctly predicted B wins, correctly predicted A wins, and the two kinds of wrong guesses. It shows whether the model is balanced or leaning one way.

Cell · confusion matrix and full report

print(confusion_matrix(y_test, predictions))
print(classification_report(y_test, predictions, digits=3))

The 2x2 grid reads: top-left and bottom-right are correct, the other two are mistakes. The report adds precision (when it predicted A wins, how often was it right) and recall (of the matches A actually won, how many it caught). For a balanced target like ours, these should all sit close to the accuracy.

Model 2: Decision Tree

A different kind of model, so you can compare. A decision tree learns a flowchart of yes/no questions about the features.

How a decision tree thinks.

Where logistic regression draws one straight dividing line, a decision tree asks a series of threshold questions, "is rank_diff below this value? if so, ask another question, otherwise ask a different one", building a flowchart that ends in a prediction. It is easy to picture and can capture patterns a straight line cannot. The exact same fit and predict pattern applies, which is the beauty of scikit-learn: swap the model, keep the workflow.

Cell · train a decision tree

tree = DecisionTreeClassifier(max_depth=4, random_state=42)
tree.fit(X_train, y_train)
tree_pred = tree.predict(X_test)

accuracy_score(y_test, tree_pred)

max_depth=4 limits how many questions deep the flowchart goes, which stops it from memorizing the training data. random_state=42 just makes the result repeatable. Expect an accuracy in the same 0.65 range.

Depth controls overfitting. A very deep tree can score near-perfect on the training data by memorizing it, then do worse on the test set, that gap is called overfitting. A shallow tree generalizes better. This is why we cap the depth, and why we always judge on the test set, never the training set.
Practice

1.Train a decision tree with max_depth=3 and print its test accuracy.

Solution
t3 = DecisionTreeClassifier(max_depth=3, random_state=42)
t3.fit(X_train, y_train)
print(round(accuracy_score(y_test, t3.predict(X_test)), 3))

2.Train a very deep tree with max_depth=20. Compare its accuracy on the training set versus the test set.

Solution
deep = DecisionTreeClassifier(max_depth=20, random_state=42)
deep.fit(X_train, y_train)
print("train acc:", round(accuracy_score(y_train, deep.predict(X_train)), 3))
print("test acc: ", round(accuracy_score(y_test, deep.predict(X_test)), 3))

The train accuracy shoots up (near memorized) while the test accuracy is lower. That gap is overfitting in action.

3.In a comment, say which tree you would trust for real predictions, the depth-3 one or the depth-20 one, and why.

Solution

The depth-3 tree, because we judge models on unseen data. The deep tree looks better on the training set only because it memorized it; on the test set (new matches) the shallow tree generalizes better, which is what matters for predicting real future matches.

Compare the models and read the story

Put everything side by side, then look at which features actually matter. This is the core of the study you will write up.

Cell · a fair comparison table

baseline_acc = accuracy_score(y_test, (test["rank_diff"] < 0).astype(int))
logreg_acc   = accuracy_score(y_test, predictions)
tree_acc     = accuracy_score(y_test, tree_pred)

results = pd.DataFrame({
    "model": ["baseline (favorite wins)", "logistic regression", "decision tree"],
    "accuracy": [baseline_acc, logreg_acc, tree_acc],
})
results

One clean table, same test set for all three, is exactly what belongs in your write-up. It lets a reader see at a glance that the models are in the same ballpark as the baseline.

Cell · which features drive the prediction?

importances = pd.Series(tree.feature_importances_, index=feature_cols)
importances.sort_values(ascending=False)

feature_importances_ tells you how much the tree leaned on each feature. You will see rank_diff (and points, which measures the same thing) dominate, with age and height barely registering. That is the headline finding: ranking is almost the whole story.

The honest conclusion of the study. All three approaches land near 0.65 to 0.68. The models barely beat the favorite baseline, and ranking is by far the most important feature. Read the right way, that is a genuine result about tennis: match outcomes are mostly explained by who is stronger on paper, and the remaining upsets are close to irreducible randomness. Reporting that honestly, with the table and the feature importances to back it, is far more impressive than claiming an unrealistic 95%.
