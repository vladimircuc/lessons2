P vs NP, from scratch

So far, every problem in the course had a fast algorithm. This unit is about problems where nobody knows one, and how you prove a problem belongs in that group.

1. Every problem is a yes/no question

Search version

Find the longest simple path from a to b.

Decision version

Is there a simple path from a to b with at least k edges? Answer YES or NO.

The HW writes each problem as the set of its YES instances:

LPATH = { (G, a, b, k) | G has a simple path from a to b with at least k edges }

"Solve LPATH" means: given some (G, a, b, k), decide whether it's in the set.

3. The four labels

P

Solvable fast

A polynomial-time algorithm answers it.

BFS shortest path, max flow, sorting

NP

Checkable fast

If the answer is YES, there's a proof (a certificate) you can check in polynomial time.

NP means "nondeterministic polynomial," not "not polynomial."

NP-complete

Hardest in NP

In NP and NP-hard.

SAT, HAMPATH, PARTITION, 3-COLOR

NP-hard

As hard as all of NP

A fast algorithm for it gives a fast algorithm for every NP problem.

Doesn't have to be in NP itself.

The map (drawn assuming P ≠ NP)
Click a card to highlight its region.
The open question. P ⊆ NP for sure: if you can solve it fast, you can check it fast. Is P = NP? Nobody knows. Most people bet no, and a proof either way wins $1,000,000.

4. Reductions: how you prove a problem is hard

Y ≤ₚ X means you can turn any instance of Y into an instance of X in polynomial time, and the answer stays the same.

Press play to send an instance through.

Why this proves X is hard

If X had a fast solver, the dashed box would be a fast solver for Y. Y is known to be hard, so X is at least as hard as Y.

Direction matters

Known hard ≤ₚ your new problem. To show LPATH is hard, turn HAMPATH instances into LPATH instances. Never the other way around.

"Same answer" has to hold both ways
Every YES goes to a YES, every NO goes to a NO.

That's why every reduction proof has two directions. (⇒) If y is YES, then f(y) is YES. (⇐) If f(y) is YES, then y was YES. The second one is the same as "NO goes to NO."

5. One trap: input size

Runtime is measured in the size of the input. Writing down a number n takes about log₂ n bits. So a loop from 1 to n is exponential in the input size.

The method

Every question in HW6 is one of four types. Read the question, pick the type, and follow its recipe.

Step 0: what does the question ask?

Type 1 Show X ∈ NP

  1. Name the certificate

    What would a "proof of YES" look like? Usually the solution itself: the path, the assignment, the factor.

  2. Write the verifier

    List the checks that confirm the certificate is valid.

  3. Show it's polynomial

    Each check is a loop over the input. Add them up.

Template
Certificate: ...
Verifier: given the input and a certificate c,
  1. check that ...
  2. check that ...
  Accept if every check passes.
Runtime: O(...), which is polynomial.

Type 2 Show X is NP-complete

  1. X ∈ NP

    Do the Type 1 recipe.

  2. Pick a known NP-complete problem Y

    The hint usually names it. Otherwise, pick the one that looks most like X.

  3. Build f: an instance of Y → an instance of X

    Say exactly what f outputs. Draw a small example.

  4. f runs in polynomial time

    Count what f adds: vertices, edges, clauses, numbers.

  5. (⇒) YES becomes YES

    Take a solution for y. Build a solution for f(y).

  6. (⇐) YES came from YES

    Take a solution for f(y). Build a solution for y. This is usually the harder direction.

Template
(1) X ∈ NP: certificate ..., verifier ..., polynomial.
(2) Reduce Y ≤ₚ X, where Y is NP-complete.
    Given an instance y of Y, f outputs ...
(3) f runs in polynomial time because ...
(4) (⇒) If y ∈ Y, then f(y) ∈ X because ...
(5) (⇐) If f(y) ∈ X, then y ∈ Y because ...
So X is NP-complete.

Type 3 If P = NP, find the actual answer

  1. Get the black box

    The yes/no version D is in NP. If P = NP, then D ∈ P. Call its fast test BOX. You can't look inside it.

  2. Ask once

    If BOX says NO, there's nothing to find.

  3. Shrink one piece at a time

    Delete a piece, or cut a range in half, and ask BOX again. Keep the change only if the answer is still YES.

  4. Argue it's correct and polynomial

    Invariant: "a solution still exists." Runtime: (number of BOX calls) × (polynomial per call).

Type 4 Show X ∈ P (or give an algorithm)

  1. Give the algorithm

    Often one you already know: BFS, Dijkstra, a greedy rule.

  2. Argue it's correct

    Why does its answer match the definition of the problem?

  3. Give the runtime

    It must be polynomial in the input size.

Common mistakes

Wrong direction. Reducing X to SAT only shows X is no harder than SAT. Reduce the known problem to X.

Only one direction. You need both (⇒) and (⇐).

Skipping X ∈ NP. NP-complete means NP-hard and in NP.

A "magic" f. f must run in polynomial time. It can't secretly solve Y first, like finding the Hamiltonian path and then building the output.

Counting in n instead of bits. For numbers, the input size is the number of bits.

Problem 1

DoubleSAT

Type 2 · NP-complete
Question. DOUBLE-SAT = {boolean formulas φ with at least two satisfying assignments}. Show DOUBLE-SAT is NP-complete. You may use: SAT is NP-complete.
The idea. Add a new variable y that the formula doesn't care about. Then every solution comes in a pair: one with y = 0, one with y = 1.
Watch the solutions double

Solve it with the method

  1. DOUBLE-SAT ∈ NP

    Certificate: two assignments A₁ and A₂. Verifier: check A₁ ≠ A₂, plug each one into φ, and check both make φ true. Plugging in takes time linear in the size of φ, so this is polynomial.

  2. Pick the known problem

    SAT. The problem gives it to you.

  3. Build f

    Given φ, output φ′ = φ ∧ (y ∨ ¬y), where y is a new variable that isn't in φ. The clause (y ∨ ¬y) is always true, so y can be anything.

  4. f is polynomial

    It adds one variable and one clause: O(size of φ).

  5. (⇒) φ ∈ SAT gives φ′ ∈ DOUBLE-SAT

    Some assignment A makes φ true. Then A with y = 0 and A with y = 1 both make φ′ true, and they're different. That's two.

  6. (⇐) φ′ ∈ DOUBLE-SAT gives φ ∈ SAT

    Take any satisfying assignment of φ′. Since φ′ = φ AND (something), it makes φ true. Drop y, and you have a satisfying assignment of φ.

Why not output φ unchanged? If φ has exactly one solution, SAT says YES but DOUBLE-SAT says NO. The answers don't match, so it's not a reduction. Try the first formula in the demo.
Problem 2

Alexander's Path

(a) Type 1 (b) Type 3
Question. A Hamiltonian path visits every vertex exactly once. HAMPATH = {graphs that have one}. (a) Show HAMPATH ∈ NP. (b) If P = NP, show you can find the path in polynomial time. The yes/no test is a black box: it only says YES or NO.
(a)HAMPATH ∈ NP
The idea. The certificate is the path itself. Checking it is easy.
Run the verifier
Certificate (an ordering of the vertices):
Pick a certificate to check.

  1. Certificate

    An ordering v₁, v₂, …, vₙ of the vertices.

  2. Verifier

    Check 1: every vertex appears exactly once. Mark each one in a "seen" array. Check 2: every consecutive pair (vᵢ, vᵢ₊₁) is an edge. That's n − 1 edge lookups.

  3. Polynomial

    O(n + m) with an adjacency list (O(n²) with a matrix). So HAMPATH ∈ NP.

(b)Find the path using only a yes/no box
The idea. Try deleting edges one at a time. If the box still says YES without an edge, that edge wasn't needed, so delete it for good. Whatever survives is the path.
FIND-HAMPATH(G):
  if BOX(G) = NO: return "no Hamiltonian path"
  for each edge e in G:
      if BOX(G − e) = YES:
          G ← G − e          # e isn't needed, delete it for good
  return the edges left in G   # exactly the path
Watch the edges get tested
being testedneeded (kept)deletedfinal path
Press Step. The first call asks BOX about the whole graph.

  1. Get the black box

    Part (a) shows HAMPATH ∈ NP. If P = NP, then HAMPATH ∈ P, so there's a polynomial-time test BOX(G).

  2. Ask once

    If BOX(G) = NO, report that there's no path.

  3. Invariant: G always has a Hamiltonian path

    We only delete an edge when BOX says the graph still has one.

  4. Every edge left is needed

    When we tried deleting edge e, BOX said NO. Later deletions only make the graph smaller, so removing e at the end still kills every Hamiltonian path.

  5. So the leftover graph is the path

    The final G has a Hamiltonian path P. If some edge e weren't on P, then G − e would still contain P, which contradicts step 4. So G has exactly P's n − 1 edges. Start at a vertex with degree 1 and walk.

  6. Polynomial

    m + 1 calls to BOX, each polynomial, plus polynomial bookkeeping.

Problem 3

Path problems

(a) Type 4 (b) Type 2
Question. G is undirected and unweighted. A simple path repeats no vertex. SPATH = {(G, a, b, k) | a simple a→b path with at most k edges}. LPATH = {(G, a, b, k) | a simple a→b path with at least k edges}. (a) Show SPATH ∈ P. (b) Show LPATH is NP-complete, using HAMPATH.
Same question, opposite difficulty. Short paths: BFS finds them fast. Long simple paths: you have to avoid repeats, and nobody knows a fast way to do that.
(a)SPATH ∈ P
The idea. "At most k edges" only needs the shortest path, and BFS finds it.
BFS from a, layer by layer
Press Run BFS.

  1. Algorithm

    Run BFS from a. It gives dist(a, b), the fewest edges on any a→b path. Answer YES if dist(a, b) ≤ k, and NO otherwise (also NO if b is unreachable).

  2. The shortest path is simple

    If it repeated a vertex, you could cut out the loop between the repeats and get a shorter path.

  3. Correct

    Some simple path has ≤ k edges ⇔ the shortest path has ≤ k edges ⇔ dist(a, b) ≤ k.

  4. Polynomial

    BFS is O(n + m). So SPATH ∈ P.

(b)LPATH is NP-complete
The idea. A Hamiltonian path is a very long path: it uses all n vertices. HAMPATH doesn't fix the endpoints, so add two "hub" vertices s and t connected to everything, and ask for a long path from s to t.
Build f(G) and see the long path
G has n = 5 vertices. Does it have a Hamiltonian path?

  1. LPATH ∈ NP

    Certificate: the path as a list of vertices. Verifier: it starts at a and ends at b, no vertex repeats, each consecutive pair is an edge, and it has ≥ k edges. All O(n + m).

  2. Pick the known problem

    HAMPATH, from the hint.

  3. Build f

    Given G with n vertices, make G′: add a new vertex s with an edge to every vertex of G, and a new vertex t with an edge to every vertex of G (no edge between s and t). Output (G′, s, t, k = n + 1).

  4. f is polynomial

    It adds 2 vertices and 2n edges.

  5. (⇒) HAMPATH YES gives LPATH YES

    G has a Hamiltonian path v₁, …, vₙ. Then s, v₁, …, vₙ, t is a simple path in G′ with n + 1 edges.

  6. (⇐) LPATH YES gives HAMPATH YES

    G′ has a simple s→t path with ≥ n + 1 edges, so it has ≥ n + 2 vertices. G′ only has n + 2 vertices, so the path uses all of them. s and t sit only at the ends, so the middle part visits all n vertices of G using G's edges. That's a Hamiltonian path in G.

A shortcut you might see: for every pair (a, b), ask LPATH(G, a, b, n − 1). That works as an algorithm, but it asks n² questions. A reduction should produce one instance, which is why the hub trick is the clean answer.
Problem 4

Bendy sticks

Type 2 · NP-complete
Question. A stick has segments of lengths ℓ₁, …, ℓₙ with hinges between them. You can fold any hinge 180°, so every segment points left or right. The stick fits in a box of length b if the folded stick spans at most b. Show BENDY is NP-complete. Hint: reduce PARTITION to BENDY.
PARTITION (known NP-complete): given numbers a₁, …, aₙ, can you split them into two groups with equal sums? Example: {3, 1, 2, 2} → {3, 1} and {2, 2}, both sum to 4.
The idea. Folding means picking right or left for each segment. Right moves add, left moves subtract. Ending where you started means right total = left total, which is a partition. Big pieces at both ends force the middle to start and end at the center of the box.
Fold the stick: 2A, A, a₁, …, aₙ, A, 2A into a box of length 2A
a-piece going right (click to flip)a-piece going left (click to flip)fixed piecessticks out of the box

Solve it with the method

  1. BENDY ∈ NP

    Certificate: a direction (→ or ←) for each segment. Verifier: walk along the stick, track your position, and record the min and max. Accept if max − min ≤ b. That's n additions: polynomial.

  2. Pick the known problem

    PARTITION, from the hint.

  3. Build f

    Let A = a₁ + … + aₙ. Output the stick 2A, A, a₁, a₂, …, aₙ, A, 2A and box length b = 2A.

  4. f is polynomial

    n + 4 numbers, each at most 2A, so each takes only one more bit than A.

  5. (⇒) Partition gives a fold that fits

    Split into groups R and L with equal sums. The 2A piece goes 0 → 2A. The A piece goes left to A, the center. Each aᵢ goes right if it's in R and left if it's in L. You never drift more than A from the center, so you stay inside [0, 2A]. R and L are equal, so you end back at A. Then the A piece goes right to 2A, and the last 2A piece goes left to 0. It fits.

  6. (⇐) A fold that fits gives a partition

    The first 2A piece fills the whole box, so it ends at a wall, say 2A. The next A piece has to go left, to the center. The last 2A piece also fills the box, so it starts at a wall. The A piece before it starts A away from that wall, which is the center. So the a-pieces start at the center and end at the center: right total = left total. That's a partition.

Why the 2A and A pieces? Without them, the middle part would start against a wall. Then its first move could stick out even when a partition exists. The end pieces park you at the center with A of room on each side, and the a-pieces add up to A, so they can never escape.
Problem 5

Factoring

Type 3 · Black box
Question. If P = NP, show you can factor a composite n in polynomial time: find p, q > 1 with n = pq. Use F = {(n, a, b) | n = pq for some a ≤ p ≤ b}. Treat F as a black box, like in Problem 2.
The idea. F answers "is there a factor in this range?" That's exactly what binary search needs.
FACTOR(n):
  lo ← 2,  hi ← n − 1
  while lo < hi:
      mid ← ⌊(lo + hi) / 2⌋
      if F(n, lo, mid):  hi ← mid        # a factor is in the left half
      else:              lo ← mid + 1    # so it must be in the right half
  p ← lo,  q ← n / p
  return (p, q)
Binary search with the F box
current range [lo, hi]midactual factors (only the box knows)

Solve it with the method

  1. Get the black box

    F ∈ NP. Certificate: the factor p. Verifier: check a ≤ p ≤ b, 1 < p < n, and n mod p = 0. Dividing numbers with B bits takes poly(B) time. So if P = NP, F has a polynomial-time BOX.

  2. Algorithm

    Binary search on [2, n − 1] with FACTOR(n).

  3. Invariant

    A factor of n lies in [lo, hi]. It's true at the start because n is composite, and each step keeps a half that has one. When lo = hi, that number is a factor p, and q = n / p.

  4. Polynomial

    The range halves every call, so there are about log₂ n calls. log₂ n is the number of bits of n, which is the input size. Each call is polynomial, so the total is polynomial.

Trap: why not try p = 2, 3, 4, … up to √n? √n = 2(bits / 2). That's exponential in the input size.

Factoring is in NP, but nobody has shown it's NP-complete or found a fast algorithm. RSA encryption depends on it staying hard.

Problem 6

Coloring a graph

Type 4 · Greedy algorithm
Question. A vertex coloring gives neighbors different colors. Every vertex has degree at most d. Give a greedy algorithm that colors the graph with d + 1 colors.
The idea. Color the vertices one at a time. A vertex has at most d neighbors, so at most d colors are blocked. With d + 1 colors, one is always free.
GREEDY-COLOR(G, d):
  for each vertex v (any order):
      blocked ← colors of v's neighbors that are already colored
      color[v] ← smallest color in {1, …, d + 1} not in blocked
Greedy coloring with d = 3, so 4 colors

Solve it with the method

  1. Algorithm

    GREEDY-COLOR, in any vertex order.

  2. It never gets stuck

    v has at most d neighbors, so at most d colors are blocked. At least one of the d + 1 colors is free.

  3. The coloring is valid

    Take any edge (u, v), and say u got colored first. When v is colored, u's color is blocked, so v picks a different one.

  4. Polynomial

    Each vertex scans its neighbors once: O(n + m) total, plus O(d) per vertex to find the free color.

The NP connection. "Can G be colored with 3 colors?" is NP-complete. Greedy guarantees d + 1 colors, not the fewest possible.
