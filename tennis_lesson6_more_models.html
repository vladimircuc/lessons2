import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import LinearSVC
from sklearn.neural_network import MLPClassifier
from sklearn.metrics import accuracy_score

df = pd.read_csv("atp_2000_2024_model_ready.csv", low_memory=False)
df["tourney_date"] = pd.to_datetime(df["tourney_date"])
df = df.sort_values("tourney_date")

feature_cols = ["rank_diff", "points_diff", "age_diff", "height_diff"]
cut = int(len(df) * 0.8)
train, test = df.iloc[:cut], df.iloc[cut:]
X_train, y_train = train[feature_cols], train["target"]
X_test,  y_test  = test[feature_cols],  test["target"]

# baseline + the three models from earlier weeks (for the final table)
baseline_acc = accuracy_score(y_test, (test["rank_diff"] < 0).astype(int))
logreg_acc = accuracy_score(y_test, LogisticRegression(max_iter=1000).fit(X_train, y_train).predict(X_test))
tree_acc   = accuracy_score(y_test, DecisionTreeClassifier(max_depth=4, random_state=42).fit(X_train, y_train).predict(X_test))
forest_acc = accuracy_score(y_test, RandomForestClassifier(n_estimators=200, max_depth=8, random_state=42, n_jobs=-1).fit(X_train, y_train).predict(X_test))
print("baseline", round(baseline_acc,3), "logreg", round(logreg_acc,3), "tree", round(tree_acc,3), "forest", round(forest_acc,3))

Scale the features

Three of this week's models measure distances or follow gradients through the features. If one feature runs in the thousands (ranking points) and another in single digits (age), the big one drowns out the small one. Scaling rewrites every feature to the same footing (mean 0, similar spread) so they count fairly.

scaler = StandardScaler().fit(X_train)     # learn the scaling from the training data only
X_train_s = scaler.transform(X_train)      # scaled training features
X_test_s  = scaler.transform(X_test)       # scaled test features
Rule of thumb: tree-based models (decision tree, random forest, gradient boosting) do not care about scale. Distance and gradient models (KNN, SVM, neural networks) do. So this week, gradient boosting uses the plain features, and the other three use the scaled ones.

Model 4: Gradient Boosting

The model competition winners reach for on tabular data. Like a random forest it is made of trees, but it builds them in a completely different way.

Gradient boosting builds trees one at a time, and each new tree is trained specifically on the mistakes the previous trees are still making. The final prediction adds them all up.

How it works, and how it differs from a random forest.

A random forest builds many trees independently and in parallel, then averages their votes. Gradient boosting builds trees in sequence: the first tree makes a rough prediction, then the second tree looks only at where the first went wrong and tries to correct it, the third corrects what is still wrong, and so on. Each tree is usually shallow (a "weak" learner), but adding hundreds of small corrections produces a very accurate model. The word "gradient" just means it uses the errors to decide what to fix next. On tables of numbers like ours, this is generally the single most powerful off-the-shelf method.

Cell · train gradient boosting (plain features, it is tree-based)

gb = GradientBoostingClassifier(max_depth=3, random_state=42)
gb.fit(X_train, y_train)
gb_pred = gb.predict(X_test)

gb_acc = accuracy_score(y_test, gb_pred)
print("gradient boosting:", round(gb_acc, 3))

Takes a few seconds (it is building 100 trees in a row). Expect ~0.64. The most powerful tabular method available, and it still lands at the ceiling, which is a strong point for your study.

3.In a markdown cell, explain the core difference between gradient boosting and a random forest. write it

Example answer

A random forest builds many trees independently and averages their votes, so the trees do not talk to each other. Gradient boosting builds trees one after another, where each new tree focuses on correcting the mistakes the previous trees made. So a forest is a parallel crowd, while boosting is a sequence of fixes that build on each other.

Model 5: K-Nearest Neighbors

The simplest idea in machine learning: to predict a new match, find the most similar past matches and copy what happened.

Each dot is a past match, placed by its features and colored by who won. For a new match (the star), KNN finds the k closest past matches (dashed circle) and takes the majority vote. Here 3 green vs 2 blue, so it predicts A.

How it works.

KNN does no real "training" at all, it just memorizes every past match. When a new match comes in, it measures the distance from that match to every stored one, picks the k nearest (say the 15 most similar matchups by ranking gap, age gap, and so on), and lets them vote. If most of those similar past matches were won by player A, it predicts A. The only knob is k: small k is jumpy and noise-sensitive, large k is smoother. Because it is built entirely on distance, this is a model where scaling the features really matters.

Cell · train KNN (scaled features)

knn = KNeighborsClassifier(n_neighbors=15)
knn.fit(X_train_s, y_train)
knn_pred = knn.predict(X_test_s)

knn_acc = accuracy_score(y_test, knn_pred)
print("KNN (k=15):", round(knn_acc, 3))

Expect a bit lower than the others, around 0.63. That dip is informative, see practice question 2.

Model 6: Support Vector Machine

A model that draws the dividing line between the two classes with the widest possible buffer around it.

An SVM places the boundary so the empty gap (margin) on either side is as wide as possible. Only the borderline points, the support vectors (circled), actually decide where it goes; the rest do not matter.

How it works.

Many lines could separate two groups of points. An SVM picks the one with the biggest empty buffer on both sides, on the theory that a boundary with lots of breathing room will generalize best to new points. Cleverly, only the handful of points right on the edge of that buffer, the support vectors, matter; move a far-away point and the boundary does not budge. SVMs can also bend the boundary into curves using something called a kernel, which makes them powerful, but that version is slow on large datasets, so on our 70,000 matches we use the fast straight-line version.

Cell · train a linear SVM (scaled features)

svm = LinearSVC(max_iter=5000)
svm.fit(X_train_s, y_train)
svm_pred = svm.predict(X_test_s)

svm_acc = accuracy_score(y_test, svm_pred)
print("linear SVM:", round(svm_acc, 3))

Expect ~0.64, right with the others. We use LinearSVC because a full curved-boundary SVM would take far too long on this many matches, which is itself a real, worth-noting limitation of SVMs.

2.In a markdown cell, explain in your own words what the "margin" and the "support vectors" are. write it

Example answer

The margin is the empty gap on either side of the boundary line, and the SVM chooses the boundary that makes this gap as wide as possible so it generalizes well. The support vectors are the few data points sitting right on the edge of that gap, and they are the only points that determine where the boundary goes. Points far from the boundary have no effect on it at all.

Model 7: Neural Network

The famous one. For a table of numbers like ours it is overkill, but building one and watching it hit the same ceiling is a great result to show.

The features enter on the left, pass through a layer of "units" that each combine and re-weight them, and end at a single output: the probability that player A wins. Training nudges every connection until those probabilities match the real results.

How it works.

A neural network is layers of simple units. Each unit takes all the numbers from the previous layer, multiplies them by its own set of weights, adds them up, and passes the result through a little on/off curve. Stack a few layers and the network can, in principle, learn very complicated patterns. Training means feeding in matches, checking how wrong the output is, and nudging every weight a tiny bit in the direction that reduces the error, over and over. This is exactly what powers image and language models, but those problems have rich structure to exploit. Our four tidy numbers do not, so here the network has little to chew on beyond what a simple line already captures.

Cell · train a small neural network (scaled features)

nn = MLPClassifier(hidden_layer_sizes=(16, 8), max_iter=300, random_state=42)
nn.fit(X_train_s, y_train)
nn_pred = nn.predict(X_test_s)

nn_acc = accuracy_score(y_test, nn_pred)
print("neural network:", round(nn_acc, 3))

hidden_layer_sizes=(16, 8) means two hidden layers, one of 16 units and one of 8. Expect ~0.64, same ceiling. A neural network with far more capacity than the problem needs still cannot beat a straight line here, which is a powerful thing to state in the write-up.

6.Explain why KNN, SVM, and neural networks need scaled features, but tree-based models do not. write it

Example answer

KNN, SVM, and neural networks all rely on distances or on adding up weighted feature values, so a feature measured in the thousands would completely overpower one measured in single digits. Scaling puts every feature on the same footing so each contributes fairly. Tree-based models only ask yes/no threshold questions about one feature at a time, so the scale of a feature does not change the splits, and scaling makes no difference to them.
