Graphs 101

A graph is dots and lines. Dots are things. Lines are connections between things. Almost every problem in this unit is a graph in disguise.

Graphs hide everywhere

Road map

Cities are dots. Roads are lines. The numbers are miles.

Friends

People are dots. A friendship is a line.

Prerequisites

Courses are dots. An arrow means "take this one first".

The vocabulary

Vertex (node)

A dot. All of them together are called V.

Edge

A line between two vertices. All of them together are called E.

Undirected

A two-way street. A-B means you can go A to B and B to A.

Directed

A one-way street. A → B does not let you go back from B to A.

Weighted

Each edge has a number: a cost, a distance, or a time. It can even be negative.

Path

A route that follows edges one after another. Here: A → B → D.

Cycle

A path that comes back to where it started. Here: A → B → C → A.

Connected component

A group that can all reach each other. No edges between different groups.

DAG

Directed Acyclic Graph: one-way edges and no cycles at all.

How the computer stores a graph

Each vertex keeps a list of its neighbors. This is called an adjacency list. Every algorithm today walks these lists. Hover over or tap a vertex.

Counting the work

V and E

We measure graph size with two numbers: V = number of vertices, E = number of edges. Some problems call them n and m.

O(V + E) is "look at everything once"

Touch every vertex a few times and every edge a few times. You can't do better, because you have to at least read the graph.

Useful fact

With V vertices, there are at most V·(V−1)/2 possible edges, one per pair. So E = O(V²).

This graph has 5 vertices and all 10 possible edges. You'll need this fact in P1.

Breadth-first search (BFS)

Explore in rings. First visit everything 1 step away, then everything 2 steps away, then 3, and so on. Like a ripple in a pond.

The idea

Uses a queue

First in, first out. Like a line at a coffee shop: new people join at the back, the front person gets served next.

out ←ABC← in

Visit each vertex once

The first time you see a vertex, mark it. Never add a marked vertex to the queue again.

Distances come free

When u discovers a new neighbor v: dist[v] = dist[u] + 1. That's the fewest edges from the start.

Watch it run

Press Play, or step through with Next. The number under each vertex is its distance from S.

not seen yetwaiting in the queuebeing processeddoneedge that discovered a vertex (BFS tree)

What BFS gives you

  • Fewest edges from the start to every vertex. That's the shortest path when edges have no weights.
  • The path itself. Each vertex remembers who discovered it (its parent). Follow parents back to the start.
  • Everything reachable from the start. Anything never marked can't be reached.
Running time

O(V + E). Each vertex goes into the queue once. Each edge gets looked at once from each end.

Bonus: counting connected components

Go through the vertices. When you find one that isn't marked yet, start a new BFS from it. That BFS marks its whole group.

Each BFS = one component. Total time is still O(V + E), because every vertex and edge belongs to exactly one BFS.

Depth-first search (DFS)

Explore like you're in a maze. Keep walking forward until you hit a dead end. Then back up one step and try the next way.

The idea

Uses a stack

Last in, first out, like a stack of plates. In code this is just recursion: the call stack does the work.

C ← topBA

Three states

unvisited, in progress (on the stack), finished (all its edges checked).

Two timestamps

A clock ticks at every event. Write start time when you enter a vertex and finish time when you leave it. Shown as start/finish.

Watch it run

This graph is directed (one-way arrows). Watch the stack grow and shrink, and watch for the red edge.

unvisitedin progresstop of the stackfinishedtree edgeback edge (cycle!)

DFS is a cycle detector

Edge to an in-progress vertex

You walked in a circle back to something you haven't finished. That's a back edge, and it means there's a cycle.

Edge to a finished vertex

That vertex is completely done and can't lead back to you. No cycle. Skip it.

Rule

A directed graph has a cycle exactly when DFS finds a back edge.

Topological sort

Put tasks in a line so that every arrow points forward. An arrow u → v means "u has to happen before v".

The idea: getting dressed

Underwear before pants. Pants before shoes. Socks before shoes. You need an order that respects every arrow.

Only works on a DAG

A cycle says "A before B before C before A". That's impossible, so a graph with a cycle has no topological order.

Many right answers

Socks first or underwear first? Both work. Any order where every arrow points forward is correct.

There are two classic ways to find one. Both take O(V + E).

Method 1: peel off what's ready

The small number on each item counts its incoming arrows (how many things must come first). Zero means it's ready.

ready (0 incoming arrows)taken nextplaced in the order

Method 2: DFS finish times

Run DFS. Each time a vertex finishes, put it at the front of the list. A vertex only finishes after everything it points to has finished, so it lands in front of all of them.

Check: line them up

Here is the order from Method 1, laid out left to right. Every arrow points right. That's what "topological order" means.

Bonus: shortest paths in a DAG

Fastest shortest paths

Go through the vertices in topological order. For each one, relax its outgoing edges once. Done in O(V + E), and negative weights are fine. (Relaxing is explained in the next tab.)

Learn · 5 of 7

Shortest paths 101

Now edges have weights. The shortest path is the one with the smallest total weight, not the fewest edges.

Fewest edges is not the same as cheapest

What BFS picks

S → A uses 1 edge. Total cost 10.

The real shortest path

S → B → A uses 2 edges. Total cost 2 + 3 = 5.

So BFS is out once weights show up. We need new tools.

Distance estimates

d[v]

The cheapest way to reach v that we've found so far. It's a guess that keeps improving.

Start

d[s] = 0 for the start. Everyone else is ∞, meaning "no way found yet".

Only goes down

Guesses only get better (smaller). When no guess can improve, every d[v] is the true distance.

Relaxation: the one move

Look at one edge u → v and ask: is going through u a cheaper way to reach v?

Big idea

Bellman-Ford and Dijkstra both do nothing but relax edges. The only difference is which order they relax them in.

Negative weights and negative cycles

Negative weights are allowed (think: a road that pays you a toll). But a cycle with a negative total breaks everything: each lap makes the path cheaper, forever.

Negative cycle

If a negative cycle can be reached from the start, shortest paths don't exist (they go to −∞). Algorithms must detect this.

Bellman-Ford

The brute-force one. Relax every edge. Then do it again. Repeat V − 1 times. It's slow, but it handles negative weights and it can catch negative cycles.

Watch it run

One round = relax every edge once, in a fixed order. We picked a bad order on purpose, so you can see why several rounds are needed. The table records d[ ] after each round.

edge being relaxededge that gave a vertex its current best valuejust improved

The round rule

Round rule

After round i, every vertex whose best path uses at most i edges has its correct distance.

  • Round 1 is guaranteed to fix the first edge of a best path, round 2 the second edge, and so on.
  • A best path never repeats a vertex, so it has at most V − 1 edges. That's why V − 1 rounds are always enough.

Catching a negative cycle

After V − 1 rounds everything should be final. So run one extra round. If anything still improves, there's a negative cycle.

Cost and two HW hints

Running time

(V − 1) rounds × E edges per round = O(V · E).

Hint for P2

If you know every best path is short (at most k edges), you can stop after k rounds.

Hint for P3

Bellman-Ford only catches negative cycles it can reach from the start. To catch all of them, add a new start that reaches everything.

Dijkstra's algorithm

The smart one. Always handle the closest unfinished vertex next. It's fast, but it only works when no weight is negative.

The idea

Water in pipes

Pour water in at s. It spreads through the pipes at a steady speed. Vertices get wet in order of distance. Once a vertex is wet, its distance is final.

Priority queue

A container that always hands you the vertex with the smallest d. Think of a "closest first" line.

Settle, then relax

Take the closest unsettled vertex. Lock its distance (settle it). Relax its outgoing edges. Repeat.

Watch it run

not reachedin the priority queueclosest, being settledsettled (final)best way in (parent edge)

Why negative edges break it

Dijkstra locks a vertex as soon as it's the closest. A negative edge found later could have made it cheaper, but it's too late.

Cost, and how it compares

Running time

With a binary heap: each vertex leaves the queue once, each edge can lower a key once, and each of those costs log V. Total O((V + E) log V).

Step 5 Tweak the graph: the toolbox

Don't change the algorithm. Change the graph so a normal algorithm answers your question.

Add a new vertex with a 0-weight edge to every vertex. One run from it reaches everything. Used in P3.

Copies (layers)

Make k + 1 copies of the graph. Copy i means "state i", like "used i red vertices". Edges move you between copies. Used in P4.

Flip the signs

HW3 · Problem 1

Power plants

The problem

Madison has n power plants and n² buildings. Some pairs are connected by two-way wires. A building has power if it's wired to a plant, or wired to a building that has power. No building can get power from two different plants. Given the list of wires W, find the plant that powers the most buildings.

Target: O(n⁴)
1Translate2Tiny example3Name it4Pick5Tweak6Check and write up

Step 1 Translate the story

n power plants
→
n vertices (squares)
n² buildings
→
n² vertices (circles)
bidirectional wires
→
Undirected edges
No costs mentioned
→
No weights
V = n + n² = O(n²)
E = number of wires ≤ number of pairs ≤ V² = (n + n²)² = O(n⁴)

Step 2 Draw a tiny example

2 plants and 9 buildings. By eye: P1 powers 3 buildings (b1, b2, b3), P2 powers 4 (b4 to b7). Buildings b8 and b9 aren't wired to any plant, so they have no power.

Step 3 Name the question

"Building b is powered by plant P" just means "you can walk from P to b along wires". In graph words: b is in P's connected component.

The question, in graph words

Which plant's connected component contains the most buildings?

Use every sentence

"No building can be powered by two plants" means each component has at most one plant. That's what makes the count clean.

Step 4 Pick the algorithm

  • No weights, only "who is connected to whom". That's BFS (DFS works just as well).
  • Check the target: BFS costs O(V + E) = O(n² + n⁴) = O(n⁴). It matches exactly.

Step 5 Tweak the graph

Nothing to tweak. BFS answers the question on the graph as it is. Only add a counter: how many building vertices each BFS reaches.

Step 6 Check it on the example

Write-up
Build
One vertex per plant and per building, one undirected edge per wire in W, stored as an adjacency list. V = n + n², E = |W| = O(n⁴).
Run
For each plant p, run BFS from p and count the building vertices it reaches.
Return
The plant with the largest count.
Why
A building is powered by p exactly when there's a path of wires from p to it, and BFS from p finds exactly the vertices with a path from p.
Time
Each component has at most one plant, so no two BFS runs explore the same vertices. All runs together touch each vertex once and each wire twice: O(V + E) = O(n² + n⁴) = O(n⁴).
Common trap

"I run BFS n times, so it's n · O(n⁴) = O(n⁵)." Not true here. Each BFS stays inside its own component, and the components don't overlap, so the total work is one pass over the graph.

In graph words

Step 4 Pick the algorithm

  • Negative weights are possible, so Dijkstra is out. That leaves Bellman-Ford.
  • But Bellman-Ford costs O(V · E), and the target is O(V + k · E). Compare them piece by piece:
Bellman-Ford: V − 1 rounds1234…V−1
Target: only k rounds1…kk+1…V−1

Each round costs O(E). Setting up d[ ] costs O(V). So O(V + k · E) reads as "set up, then k rounds".

Step 5 Tweak: stop early

Run Bellman-Ford for k rounds instead of V − 1. The round rule from the Bellman-Ford tab says why that's enough:

Why k rounds are enough

After round i, every vertex whose best path uses ≤ i edges is correct. In a k-limited graph, every vertex has a best path with ≤ k edges. So after round k, every vertex is correct.

Step 6 Check it on the example

The edges are relaxed in a bad order on purpose. Even so, everything is final after round 2.

Write-up
Build
Nothing new. Use the graph as given.
Run
Set d[s] = 0 and every other d[v] = ∞. Then do k rounds; in each round, relax every edge once.
Return
d[v] for every vertex v.
Why
After round i, d[v] is at most the weight of the best path to v that uses ≤ i edges (round rule). Every v has a best path with ≤ k edges, so after k rounds d[v] ≤ δ(s, v). Every d[v] is always the weight of some real path, so it can't go below δ(s, v). So d[v] = δ(s, v).
Time
Setup O(V), plus k rounds of O(E) each: O(V + k · E).
HW3 · Problem 3

Conservative cycles

The problem

There are n particle locations and O(n) transitions. A transition (ℓi, ℓj, wij) moves a particle from ℓi to ℓj and takes wij work, which can be a positive or negative integer. Transitions are one-way. The force field is conservative if the total work around every closed loop is zero. Decide if the field is conservative.

Target: O(n²)

3 − 1 − 2 = 0 ✓
3 − 1 − 1 = +1 ✗
1 − 2 − 1 = −2 ✗

Only the first one is conservative. One bad cycle anywhere is enough to say "not conservative".

Step 3 Name the question

In graph words

Is there any cycle whose total is not 0? If yes, not conservative. If no, conservative.

"Not 0" means one of two things:

Total < 0a negative cycle

Step 4 Pick the algorithm

  • Finding a negative cycle is exactly what Bellman-Ford's extra round does.
  • Check the target: Bellman-Ford costs O(V · E) = O(n · n) = O(n²). It matches.
  • Two gaps remain: Bellman-Ford doesn't find positive cycles, and it only sees cycles it can reach from its start. Step 5 fixes both.

Step 5 Tweak the graph (two tricks)

Trick A: flip the signs

Original

The cycle adds up to 3 − 1 = +2. Bellman-Ford can't see positive cycles.

Every weight × (−1)

Now it adds up to −3 + 1 = −2. Bellman-Ford catches it.

So run Bellman-Ford twice: on the original graph (finds negative cycles) and on the flipped graph (finds positive cycles).

Trick B: a super source

Problem

Starting from a, Bellman-Ford never reaches d or e, so it never sees their cycle.

Fix

Add a new vertex s* with a 0-weight edge to every vertex. Now every cycle is reachable.

Does s* create fake cycles?

No. s* has only outgoing edges, so no cycle can pass through it. The cycles are exactly the original ones.

Step 6 Check it on the example

Two islands: the triangle a, b, c adds up to 0, and the pair d, e adds up to +2. Each step below is one full round.

Write-up
Build
One vertex per location, one directed edge per transition with weight wij. Add s* with a 0-weight edge to every vertex. V′ = n + 1, E′ = O(n) + n = O(n). Also build a copy with every weight multiplied by −1.
Run
Bellman-Ford from s* on both graphs, including the extra cycle-check round.
Return
"Conservative" if neither run finds a negative cycle. Otherwise "not conservative".
Why
A cycle with a nonzero total is negative in the original graph or negative in the flipped graph. s* reaches every vertex and adds no new cycles, so Bellman-Ford sees every cycle.
Time
Each run is O(V′ · E′) = O(n · n) = O(n²). Two runs: O(n²).
HW3 · Problem 4

Color limit

The problem

Every vertex is colored red or blue. All edge weights are positive. Given k, find the minimum-weight path from blue vertex s to blue vertex t that passes through red vertices at most k times, or report that no such path exists.

Target: efficient
1Translate2Tiny example3Name it4Pick5Tweak6Check and write up

Step 1 Translate the story

"weighted directed graph", "positive weights"
→
One-way edges, all weights > 0
"red or blue"
→
A label on each vertex
"at most k red vertices"
→
A budget the path must stay under

Step 2 Draw a tiny example

Change k to see how the best allowed path changes. The cheapest path overall uses 2 red vertices, so it's only allowed when k ≥ 2.

blue vertexred vertexbest path allowed for this k

Step 3 Name the question

In graph words

Shortest path from s to t, but the path can use at most k red vertices.

Plain Dijkstra would return s → a → b → t (cost 3). With k = 1 that's not allowed, because it uses 2 reds. The algorithm has to remember how many reds it has used.

Step 4 Pick the algorithm

  • All weights are positive, so Dijkstra is the tool. "Efficient" with positive weights almost always means Dijkstra.
  • Dijkstra only knows "where am I". We need "where am I and how many reds have I used". The hint says: make copies.

Step 5 Tweak: build floors

Make k + 1 copies of the graph, stacked like floors of a building. Floor i means "I've used i reds so far." Here k = 1, so there are 2 floors.

Original edge u → v (weight w)In the floor graph, for each floor i
v is blueuᵢ → vᵢ (same floor, weight w)
v is reduᵢ → vᵢ₊₁ (one floor up, weight w), only if i < k
  • Entering a red vertex costs one floor. There's no floor above k, so no path can use more than k reds.
  • Weights don't change, so a path's cost is the same on the floors as in the original graph.
  • Red copies on floor 0 can never be entered (entering a red always goes up), so they stay faded.

Step 6 Check it on the example

Run normal Dijkstra from s₀ on the floor graph. Then the answer is the smallest of d(t₀), d(t₁), …, d(tₖ).

Write-up
Build
For every vertex v, make copies v₀, v₁, …, vₖ. For every edge (u, v, w) and every floor i: if v is blue, add uᵢ → vᵢ with weight w; if v is red and i < k, add uᵢ → vᵢ₊₁ with weight w. V′ = (k + 1)·V, E′ ≤ (k + 1)·E.
Run
Dijkstra from s₀ (all weights are positive).
Return
The smallest d(tᵢ) for i = 0 … k. Follow parent pointers to get the path, and drop the floor numbers. If every d(tᵢ) is ∞, report that no path exists.
Why
A path from s₀ to tᵢ in the floor graph matches a path from s to t in G that passes through exactly i red vertices, with the same weight. Floors stop at k, so only paths with ≤ k reds exist.
Time
Dijkstra on V′ and E′: O((V′ + E′) log V′) = O(k · (V + E) · log(k · V)).
Pattern to remember

When a problem says "at most k times", make k + 1 copies of the graph and let the copy number count.
