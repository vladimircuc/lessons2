Reshape into a real prediction problem

This is the heart of the whole project. Go to your ## Build Features section from last week.

First, delete last week's feature lines. In your Build Features section you have four lines that look like df["rank_diff"] = df["loser_rank"] - df["winner_rank"] and so on. Delete all four. They used winner and loser directly, which leaks the answer. You are replacing them with the version below.

Task A · make the target

Randomly assign each match's winner to be player A or player B, then create a target column that is 1 when A won. Print the balance.

Solution
rng = np.random.default_rng(42)   # fixed seed so it repeats

# coin flip per match: is the winner player A?
df["winner_is_A"] = rng.random(len(df)) < 0.5

# target: 1 if player A won, 0 if player B won
df["target"] = df["winner_is_A"].astype(int)

df["target"].value_counts(normalize=True)

You should see

Two values, both close to 0.50. That balance is the point: the model starts from a coin flip and must earn accuracy from the features.

Task B · rebuild the features from A and B

Recreate the four difference features, but as player A minus player B, using a small helper so who-is-A is handled correctly.

Solution
# player A's value minus player B's value, based on the coin flip
def a_minus_b(winner_col, loser_col):
    a = np.where(df["winner_is_A"], df[winner_col], df[loser_col])
    b = np.where(df["winner_is_A"], df[loser_col], df[winner_col])
    return a - b

df["rank_diff"]   = a_minus_b("winner_rank", "loser_rank")
df["points_diff"] = a_minus_b("winner_rank_points", "loser_rank_points")
df["age_diff"]    = a_minus_b("winner_age", "loser_age")
df["height_diff"] = a_minus_b("winner_ht", "loser_ht")

df[["target", "rank_diff", "points_diff", "age_diff", "height_diff"]].head()

You should see

A table with the target and four features. Unlike last week, rank_diff is now positive or negative roughly equally, because A is random. The signal is still in there, the model just has to find it.

Add a markdown note for this section: "Relabeled players as A and B with a random coin flip so the target is balanced. Features are now A minus B, built only from pre-match columns (rank, points, age, height). No post-match stats, to avoid leakage." That note shows you understand exactly why this step exists.

## Train / Test Split

Your task

Split the data by time: train on the earlier 80% of the season, test on the later 20%. Print the two sizes.

Solution
df_sorted = df.sort_values("tourney_date")   # oldest first

cutoff = int(len(df_sorted) * 0.8)
train = df_sorted.iloc[:cutoff]              # earlier matches
test  = df_sorted.iloc[cutoff:]              # later matches

print("train:", train.shape[0], " test:", test.shape[0])

You should see

Two numbers that add up to your total match count, roughly an 80/20 split. The test set is the later part of the season, matches the model will not have trained on, which is the honest way to judge a predictor.

Why time-based, not random. In real life you predict an upcoming match from past results. Training on early-season matches and testing on late-season ones mirrors that exactly, so the test score reflects how the model would really perform.
