1. Driver HAS License

PhoneNumbers = (licenseNumber, state[fk1], phoneNumbers)
fk1: licenseNumber, state → DriverandLicense(licenseNumber, state)

  • False

Solution

True

HAS is 1:1 with total participation on both sides, so the merged relation approach is legal, and either entity’s key can be the PK. Database design concepts

6 points

1. Primary key for hotel reservations

  • Each reservation is for one guest, in one room, at one hotel branch, for a specific period.
  • Guests are uniquely identified by guest_id, and branches by branch_id.
  • Rooms are identified by room_number, which is only unique within a branch.
  • A guest can’t book the same room for overlapping dates. A new reservation for a room can only begin after the previous one has ended.

Which set of attributes best serves as the primary key for the Reservations table?

  • Room Number, Branch ID
  • Guest ID, Room Number, Branch ID
  • Room Number, Branch ID, Check-in Date
  • Guest ID, Room Number, Branch ID, Check-in Date

Solution

Room Number, Branch ID, Check-in Date

A reservation is one room, at one branch, for one period. Room numbers repeat across branches, so the room needs both room_number and branch_id. The same room is booked many times, so the check-in date separates the bookings, and since bookings can’t overlap, no two share a room and a check-in date. Adding guest ID would allow two guests to book the same room on the same day, and the key wouldn’t be minimal.

2. Why the employee counts are wrong

Each employee belongs to exactly one department, and dept_id in Employees correctly references Departments. An analyst needs every department with its number of employees, showing 0 for empty departments, and writes:

SELECT d.dept_id, COUNT(*) AS employee_count
FROM departments d
LEFT JOIN employees e ON d.dept_id = e.dept_id
GROUP BY d.dept_id;

The query runs, but the counts are wrong for departments with no employees. Which explanation is best?

  • An INNER JOIN should have been used, because a LEFT JOIN doesn’t allow accurate aggregation when NULL values are present in the result set.
  • The LEFT JOIN correctly produces a single row for each department with no employees, and COUNT(*) counts that row as one employee.
  • The GROUP BY clause only forms groups from rows that match in both tables, which miscounts the non-matching rows.
  • COUNT(*) is used improperly. It should be COUNT(d.dept_id) to count the department records in each group.

Solution

The second option

The LEFT JOIN keeps every department, so an empty department still produces one row, with NULLs in the employee columns. COUNT(*) counts rows, so that department shows 1. The fix is COUNT(e.dept_id) or any employee column, which skips NULLs and returns 0. An INNER JOIN would drop empty departments entirely, and COUNT(d.dept_id) still counts the row.

1. Primary key for surgical schedules

  • Surgeons are uniquely identified by surgeon_id, and operating rooms by room_number.
  • A surgeon can operate in different rooms during the day, and a room can host many surgeries, but only one at a time.

surgeon_id, scheduled_time
