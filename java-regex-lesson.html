Three methods take a pattern

These look like normal String methods, but the argument is a pattern, not plain text. That is the part everyone forgets.

matches(pattern)

Returns true or false. The entire string has to fit the pattern. Not part of it, all of it.

"cat".matches("[a-z]{3}")      // true
"cats".matches("[a-z]{3}")     // false, that is four letters
"the cat".matches("[a-z]{3}")  // false, the extra text still counts

split(pattern)

Cuts a string into a String[] everywhere the pattern matches. The matched text disappears, you keep the pieces around it.

"a,b,c".split(",")        // {"a", "b", "c"}
"a,  b ,c".split("[ ,]+") // {"a", "b", "c"}

That + is doing real work. Without it, a comma followed by a space counts as two separators and you get an empty string wedged in the middle.

replaceAll(pattern, text)

Swaps every match for the replacement. You probably will not need it tonight, but it takes a pattern too, so it belongs in the same mental bucket.

"a1b2".replaceAll("\\d", "#") // "a#b#"

The trap. matches() is all or nothing. If you want to know whether a pattern shows up somewhere inside a longer string, matches() returns false and you will think your pattern is broken. Searching inside text is a job for Pattern and Matcher, which these labs do not use.

Why Problem 5 has four backslashes

Backslashes are special twice. Two different things strip them before your pattern ever runs.

1. You type this in the source
"\\\\"
→
2. Java builds this String
\\
→
3. The pattern looks for
\

Step 1, the compiler

Inside quotes a backslash starts an escape. \n is a newline, \" is a quote, and \\ is one plain backslash. So the four characters you typed are only two by the time the String exists in memory.

Step 2, the pattern engine

Now the pattern reads that two character String. In pattern language a backslash is also special, so \\ means "one literal backslash" and \. means "one literal dot". Two characters become one again.

How to get it right every time. Write the pattern on paper with single backslashes, the normal way. Then double every backslash as you copy it inside the quotes. \d{5} becomes "\\d{5}", \. becomes "\\.", and one backslash becomes "\\\\".

Problem 1, the Math class

Lab 1. Random ranges, rounding, radians, and integer overflow.

The random formula, memorize this one. For a random int from low to high inclusive, count how many values that is, then shift:

int n = (int)(Math.random() * (high - low + 1)) + low;

For a random double from low inclusive to high exclusive, no cast and no plus one:

double d = Math.random() * (high - low) + low;

1aRandom odd number from 11 through 25 inclusive, stored in level

Show the answer 
int level = (int)(Math.random() * 8) * 2 + 11;

Count the odd numbers first: 11, 13, 15, 17, 19, 21, 23, 25. That is 8 values, not 15. Pick one of 8, double it to step by twos, then shift the start to 11.

1bRandom lowercase letter from 'a' through 'z', stored in letter

Show the answer 
char letter = (char)((int)(Math.random() * 26) + 97);

26 letters, so Math.random() * 26 gives 0 through 25. Add 97 to land on 97 through 122, then cast to char to turn the number into the letter.

You can write + 'a' instead of + 97, Java treats the char as its Unicode value in arithmetic.

1cWhy does Integer.MAX_VALUE * 2 evaluate to -2?

Show the answer

MAX_VALUE in binary is a 0 followed by 31 ones. Multiplying by 2 shifts every bit one place left, so the leading 0 falls off the front, a 1 slides into the sign bit, and a 0 fills the empty spot on the right.

You end up with 31 ones followed by a 0. In two's complement, all ones is -1, and all ones with the last bit cleared is -2.

The other way to say it: the true answer needs 33 bits, an int only has 32, so the extra bit is discarded and the value wraps around.

1dDifference between Math.round(), Math.ceil(), and Math.floor()

Show the answer
  • round goes to the nearest whole number, and a .5 tie goes up.
  • ceil always goes up, to the smallest whole number that is not smaller.
  • floor always goes down, to the largest whole number that is not larger.

Negatives are where people get burned. Math.floor(-2.1) is -3, because down means more negative. Math.round(-2.5) is -2, because the tie always goes up.

Return types differ too. ceil and floor hand back a double, round hands back a long when you give it a double.

1eWhat is printed?

double x = Math.ceil(4.2);
double y = Math.floor(7.9);
double z = Math.round(3.6);
System.out.println(x + y + z);
Show the answer 
16.0

x is 5.0, y is 7.0, z is 4. The round call returns a long, but storing it in a double widens it to 4.0, so the sum is 16.0 and prints with the decimal point.

1fWhat is wrong with this attempt at the sine of 30 degrees?

double angle = 30;
double result = Math.sin(angle);
Show the answer

Java trig functions take radians, not degrees. This computes the sine of 30 radians, which is about -0.988, nowhere near the 0.5 he wanted.

double result = Math.sin(Math.toRadians(30));  // 0.49999999999999994

Math.sin(30 * Math.PI / 180) works too, toRadians is just the readable version.

1gRandom int for a building with floors -5 through 12 inclusive

Show the answer 
int floor = (int)(Math.random() * 18) - 5;

How many floors? 12 minus -5 plus 1 is 18. Subtracting a negative is the step people rush, so write it out.

1hRandom double from 12.5 inclusive to 25.5 exclusive

Show the answer 
double health = Math.random() * 13 + 12.5;

The gap is 13.0. No cast and no plus one here, because doubles fill the whole range continuously. Math.random() already gives you 0 inclusive to 1 exclusive, which is exactly the shape you want.

1iWhat is printed, and why?

int x = Integer.MIN_VALUE;
x--;
System.out.println(x);
Show the answer 
2147483647

MIN_VALUE is a 1 followed by 31 zeros. Subtracting 1 borrows across every zero, leaving a 0 followed by 31 ones, which is MAX_VALUE.

Same wrap-around as 1c, running the other direction. Push past the bottom and you appear at the top.

1jHow do you get the last digit of a number? The last two digits?

Show the answer 
n % 10    // last digit
n % 100   // last two digits
n / 10    // chop the last digit off

That last one is the partner trick. % reads a digit, / throws it away, and together they let you walk through a number one digit at a time. Problem 2 uses exactly this.

1kRaise n to the power of its own digit count

Show the answer 
int numDigits = countDigits(n);
double result = Math.pow(n, numDigits);

Math.pow always returns a double, even when both arguments look like ints. If you need an int back, cast it: (int) Math.pow(n, numDigits).

Problem 2, evil numbers

Lab 2. A number is evil when its binary form has an even count of 1s. 3 is 11 in binary, two ones, evil. 4 is 100, one 1, not evil.

2aTake a base 10 number, convert to a binary String

public static boolean isEvilNumber(int baseTenNum) {
    // your code here
}
Show the answer 
public static boolean isEvilNumber(int baseTenNum) {
    String binary = Integer.toBinaryString(baseTenNum);
    int count = 0;
    for (int i = 0; i < binary.length(); i++) {
        if (binary.charAt(i) == '1') {
            count++;
        }
    }
    return count % 2 == 0;
}
  • charAt returns a char, so compare against '1' in single quotes, not "1" in double quotes.
  • Return the whole condition count % 2 == 0. Writing if (...) return true; else return false; works but is the long way around.

2bTake the binary number as an int, no String allowed

Here 101 means the binary number 101, so use the last digit trick from 1j.

Show the answer 
public static boolean isEvilBinary(int binaryNum) {
    int count = 0;
    while (binaryNum > 0) {
        if (binaryNum % 10 == 1) {
            count++;
        }
        binaryNum /= 10;
    }
    return count % 2 == 0;
}

% 10 peels off the rightmost digit, /= 10 discards it, and the loop ends when there is nothing left.

The worksheet has a bug. Both versions are written as isEvilNumber(int). Java cannot hold two methods with the same name and the same parameter list in one class, so that will not compile. Overloading needs different parameter types or counts. Rename one, which is why the second answer says isEvilBinary.

Problem 3, rotating a point

Lab 1. Rotate (x, y) about the origin and return the new coordinates in a double[] of length 2.

The three things this problem is testing

  • Converting degrees to radians before any trig call.
  • Computing both new values from the original x and y.
  • Building and returning an array from inside a method.
x' = x * cos(angle) - y * sin(angle)
y' = x * sin(angle) + y * cos(angle)

3Write rotatePoint

public static double[] rotatePoint(double x, double y, double angleDeg) {
    // your code here
}
Show the answer 
public static double[] rotatePoint(double x, double y, double angleDeg) {
    double rad = Math.toRadians(angleDeg);
    double newX = x * Math.cos(rad) - y * Math.sin(rad);
    double newY = x * Math.sin(rad) + y * Math.cos(rad);
    return new double[]{newX, newY};
}
  • Convert once at the top and reuse rad, rather than calling toRadians four times.
  • Do not assign back into x before computing newY. If you overwrite x first, the second line uses the rotated value and the answer is wrong.
  • new double[]{newX, newY} builds and returns the array in one line.

What the example actually prints

double[] result = rotatePoint(3, 4, 90);
System.out.println(result[0] + ", " + result[1]);
Show the answer 
-4.0, 3.0000000000000004

The worksheet says -4.0, 3.0, and the math is right, but doubles cannot store cos(90 degrees) as exactly zero. It comes out as roughly 0.0000000000000000612, and that dust survives into the y value.

Not a bug in your code. This is why you never compare doubles with ==, you check whether the difference is smaller than some tiny tolerance instead.

Problem 4, array searching

Lab 2. Two boolean methods over an int[]. Both hinge on where you put the return.

4ahasLargeNumber, true if any element is greater than 100

hasLargeNumber(new int[]{12, 45, 101, 67})  // true
hasLargeNumber(new int[]{12, 45, 99, 67})   // false
Show the answer 
public static boolean hasLargeNumber(int[] arr) {
    for (int num : arr) {
        if (num > 100) {
            return true;
        }
    }
    return false;
}

This is the "does any" shape. Return true the instant you find one, and return false only after the loop has finished and found nothing.

The classic bug is putting return false in an else inside the loop. That answers the whole question from the first element alone.

4bisIncreasingByTwos, true if every element is 2 more than the one before it

isIncreasingByTwos(new int[]{2, 4, 6, 8, 10})  // true
isIncreasingByTwos(new int[]{2, 4, 6, 7})      // false
Show the answer 
public static boolean isIncreasingByTwos(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        if (arr[i] - arr[i - 1] != 2) {
            return false;
        }
    }
    return true;
}
  • This is the "do all" shape, the mirror image of 4a. Return false on the first failure, true only at the very end.
  • Start at i = 1, not 0. Comparing pairs means the first element has nothing before it, and arr[-1] throws ArrayIndexOutOfBoundsException.
  • A for-each loop cannot do this one. You need the index to reach the previous element.

Two shapes to keep straight. "Does any element..." starts at false and returns true early. "Do all elements..." starts at true and returns false early. Almost every array boolean question on the milestone is one of these two.

Problem 5, file paths

Write each answer on paper before you open anything.

String path = "C:\\Users\\Bautista\\Documents\\report.txt";
String[] parts = path.split("\\\\");

5aWhat does System.out.println(path) print?

Show the answer 
C:\Users\Bautista\Documents\report.txt

Single backslashes. Each \\ in the source is already one backslash by the time the String exists. Printing does not put anything back.

5bWhy does split use \\\\ instead of a single \?

Show the answer

Because two layers each eat one. The compiler turns the four characters \\\\ into the two character String \\, and the pattern engine reads \\ as one literal backslash.

A single \ never survives the compiler at all, and a pattern of just \ would be a backslash with nothing after it, which is not valid.

5cWhat happens if you run path.split("\")?

Show the answer

It does not compile. Inside quotes \" means "an actual quote character", so the String is never closed and the compiler stops on that line.

Worth knowing the near miss: path.split("\\") compiles fine, then crashes at run time with a PatternSyntaxException, because the pattern is a lone backslash escaping nothing.

5dWrite the pattern for a valid file name: letters only, then a dot, then an extension.

if (fileName.matches("________________"))
Show the answer 
if (fileName.matches("[a-zA-Z]+\\.[a-zA-Z]+"))
  • [a-zA-Z]+ is one or more letters, no digits allowed.
  • \\. is a real dot. A plain . matches any character, so reportXtxt would sneak through.
  • No ^ or $ needed, matches() already checks the whole string.

If the teacher wants specific extensions only: "[a-zA-Z]+\\.(txt|java)".

Problem 6, school emails

A valid email is two letters, then exactly five digits, then @pausd.us. Find them all and store them as Email objects.

public static void main(String[] args) {
    String data = "ab12345@pausd.us, xy67890@pausd.us, invalid@pausd.us";

    // 1. make the ArrayList
    ________________________________

    // 2. write the pattern
    String emailRegex = __________________

    // 3. split into tokens
    String[] tokens = __________("[ ,]+");

    // 4. keep the valid ones
    for (String ___ : ________) {
        if (t.matches(__________)) {
            validEmails.add(___);
        }
    }
}

6Build the pattern, then fill in the program

Show the full solution 
ArrayList<Email> validEmails = new ArrayList<Email>();

String emailRegex = "[a-zA-Z]{2}\\d{5}@pausd\\.us";

String[] tokens = data.split("[ ,]+");

for (String t : tokens) {
    if (t.matches(emailRegex)) {
        validEmails.add(new Email(t));
    }
}

ab12345@pausd.us and xy67890@pausd.us go in the list. invalid@pausd.us is rejected, it has no two-letters-then-five-digits prefix.

  • add(new Email(t)), not add(t). The list holds Email objects and t is a String, so add(t) will not compile.
  • pausd\\.us, not pausd.us. An unescaped dot matches anything, so ab12345@pausdXus would pass.
  • [ ,]+ treats a comma plus a space as one separator. Drop the + and you get empty strings between the emails.

+1Push yourself

Change the pattern so it accepts either @pausd.us or @student.pausd.us. Test it before you look.

Show one answer 
"[a-zA-Z]{2}\\d{5}@(student\\.)?pausd\\.us"

(student\\.)? is a group with ? after it, so the whole group appears either zero times or one time.
