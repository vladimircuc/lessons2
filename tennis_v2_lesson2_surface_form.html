import pandas as pd
import numpy as np
from collections import defaultdict, deque
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

df = pd.read_csv("atp_2000_2024_model_ready.csv", low_memory=False)
df["tourney_date"] = pd.to_datetime(df["tourney_date"])
df = df.sort_values(["tourney_date", "match_num"]).reset_index(drop=True)
is_A = df["winner_is_A"].values.astype(bool)
cut = int(len(df) * 0.8)

def dynamic_k(n):
    return 250 / ((n + 5) ** 0.4)

# rebuild overall Elo from last week
elo = defaultdict(lambda: 1500.0); games = defaultdict(int)
elo_w = np.zeros(len(df)); elo_l = np.zeros(len(df))
for i, row in enumerate(df.itertuples(index=False)):
    w, l = row.winner_id, row.loser_id
    a, b = elo[w], elo[l]
    elo_w[i] = a; elo_l[i] = b
    exp = 1 / (1 + 10 ** ((b - a) / 400))
    elo[w] = a + dynamic_k(games[w]) * (1 - exp)
    elo[l] = b - dynamic_k(games[l]) * (1 - exp)
    games[w] += 1; games[l] += 1
df["elo_diff"] = np.where(is_A, elo_w - elo_l, elo_l - elo_w)

baseline_acc = accuracy_score(df.iloc[cut:]["target"], (df.iloc[cut:]["rank_diff"] < 0).astype(int))
print("baseline:", round(baseline_acc, 3))

Baseline near 0.637, and elo_diff is back. Now we add to it.

Today's plan: build surface Elo (the win), build recent form (a new technique), then measure both honestly. One will move the number, one mostly will not, and knowing the difference is the real skill.

Surface-specific Elo

A big idea with a one-line code change: give every player a separate rating on each surface.

Why. Surfaces play completely differently. Clay is slow and rewards patient defenders; grass is fast and rewards big serves; hard is in between. A player can be elite on one and ordinary on another, so a single Elo blurs those together and throws away real signal. The fix: keep one rating per player per surface, and when two players meet on clay, read and update only their clay ratings.

The only new idea: a pair key

Last week the ratings dictionary was keyed by player: elo[player_id]. This week it is keyed by the pair of player and surface: surface_elo[(player_id, surface)]. That tuple key is the entire change. Everything else is the same loop.

Cell · surface Elo

surface_elo = defaultdict(lambda: 1500.0)     # keyed by (player, surface)
surface_games = defaultdict(int)               # match count per (player, surface)
selo_w = np.zeros(len(df)); selo_l = np.zeros(len(df))

for i, row in enumerate(df.itertuples(index=False)):
    w, l, s = row.winner_id, row.loser_id, row.surface
    a, b = surface_elo[(w, s)], surface_elo[(l, s)]     # this surface only
    selo_w[i] = a; selo_l[i] = b                         # READ first
    exp = 1 / (1 + 10 ** ((b - a) / 400))
    surface_elo[(w, s)] = a + dynamic_k(surface_games[(w, s)]) * (1 - exp)
    surface_elo[(l, s)] = b - dynamic_k(surface_games[(l, s)]) * (1 - exp)
    surface_games[(w, s)] += 1; surface_games[(l, s)] += 1

df["surface_elo_diff"] = np.where(is_A, selo_w - selo_l, selo_l - selo_w)

Same read-then-update shape as overall Elo. The only differences: the key is (player, surface), and each surface rating uses its own match count for the step size.

Notice a trade-off you just created: splitting into three ratings means each one is trained on only part of a player's matches, so surface Elo is a bit noisier per match than overall Elo, especially on surfaces a player rarely plays. Hold that thought, the next tab measures whether it is worth it.

Example answer

The only change is the dictionary key: instead of storing one rating per player, we store one rating per player-and-surface pair. This makes sense because tennis surfaces play very differently and a player's skill is not the same on all of them, so a clay rating and a grass rating capture something a single overall rating cannot. When two players meet, we use only their ratings for the surface they are actually playing on.

Does surface Elo make sense, and does it help?

Sanity check: the best players per surface

If surface Elo is real, the top of each surface should match tennis reality. Look at the top three per surface (players with at least 50 matches on it):

names = df.drop_duplicates("winner_id").set_index("winner_id")["winner_name"]
for surf in ["Clay", "Grass", "Hard"]:
    ratings = {pid: v for (pid, s), v in surface_elo.items()
               if s == surf and surface_games[(pid, surf)] >= 50}
    top = pd.Series(ratings).sort_values(ascending=False).head(3)
    print(surf, "->", [f"{names.get(p, p)} {round(v)}" for p, v in top.items()])

But does it improve predictions?

Here is the honest test. Compare overall Elo alone, surface Elo alone, and the two together:

train, test = df.iloc[:cut], df.iloc[cut:]
def acc(cols):
    m = LogisticRegression(max_iter=1000).fit(train[cols], train["target"])
    return round(accuracy_score(test["target"], m.predict(test[cols])), 4)

print("overall Elo alone: ", acc(["elo_diff"]))
print("surface Elo alone: ", acc(["surface_elo_diff"]))
print("both together:     ", acc(["elo_diff", "surface_elo_diff"]))

Roughly 0.6425, 0.6414, and 0.6461. Read that carefully: surface Elo alone is slightly worse than overall Elo alone, but the two together beat both.

The insight. Surface Elo alone is noisier (each rating sees only part of the data), so on its own it does not win. But it carries information overall Elo lacks, how a player does on this specific surface. Overall Elo carries the broad skill signal. Give the model both the general and the specific signal and it does better than with either alone. "More specific" is not automatically better; the win comes from combining specific and general.

Recent form and the rolling window

A new tool: a record that remembers only the last few matches and forgets the rest.

The idea. Elo measures long-run skill and moves slowly on purpose. Recent form asks a different question: is this player hot or cold right now? You measure it as the win rate over their last handful of matches, say the last 10.

The new technique: a rolling window

Last week your records grew forever (total matches, full Elo history). Form is different, you only want the most recent 10 results. That calls for a rolling window: a list that automatically drops its oldest item when a new one arrives and it is full.

A rolling window of the last 10 matches. When a new result comes in, the oldest slides out, so the window always reflects current form. Python's deque(maxlen=10) does this automatically.

Cell · recent form (last-10 win rate)

recent = defaultdict(lambda: deque(maxlen=10))   # last 10 results per player
form_w = np.full(len(df), 0.5)                    # default 0.5 when no history yet
form_l = np.full(len(df), 0.5)

for i, row in enumerate(df.itertuples(index=False)):
    w, l = row.winner_id, row.loser_id
    if recent[w]:                                 # READ: win rate over the window
        form_w[i] = sum(recent[w]) / len(recent[w])
    if recent[l]:
        form_l[i] = sum(recent[l]) / len(recent[l])
    recent[w].append(1)                           # UPDATE: winner gets a 1, loser a 0
    recent[l].append(0)

df["form_diff"] = np.where(is_A, form_w - form_l, form_l - form_w)
Two details. deque(maxlen=10) is the rolling window, appending an 11th item silently drops the 1st. And a player with no matches yet has an empty window, so we default their form to 0.5, a neutral "we do not know."

2.In a markdown cell, explain what a rolling window is and why form needs one but total wins does not. write it

Example answer

A rolling window keeps only the most recent items and drops older ones as new ones arrive. Form needs one because "recent form" is about how a player is doing lately, so results from years ago should not count, only the last handful. Total wins is a lifetime count where every match should be included forever, so it just grows and never forgets. The two features ask different questions, so they use different kinds of memory.

Roughly: baseline 0.637, Elo 0.643, Elo + surface 0.646, and Elo + surface + form 0.645.

Two honest findings, both worth stating in your report.
1. Surface Elo helps. Adding it took you from 0.643 to about 0.646, the biggest single jump of the project so far. The general-plus-specific combination is a real win.
2. Recent form does not. Adding form on top barely changed the number (and nudged it down slightly). That is not a bug, it is a genuine result: Elo already updates after every match, so "recent form" is largely information the model already has. A feature that duplicates what you already know does not add much.
This is real data science. Half the job is inventing features; the other half is measuring them and being willing to say "that one did not help." Surface Elo earns its place in the final model. Form is a judgment call, keep it if you like, but the honest report says it added nothing. Learning to tell those apart, with a measurement instead of a hunch, is exactly the skill this chapter is building.
