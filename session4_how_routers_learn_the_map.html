Network interview prep. Session 4.

How routers learn the map

In session 2 a router looked up the destination in a table and sent the packet on. Where did that table come from? This session is the two ways routers build it, and why the one built for the whole internet also runs inside Meta's data centers.

Start here

Every router has a table that says "for addresses like this, send the packet that way." Session 2 showed the lookup. This session is about where the entries come from. There are only three answers:

  1. It's plugged in. A router knows the networks on its own ports without being told.
  2. A person typed it. Fine for small networks, and for "everything else goes to the internet."
  3. The routers told each other. This is a routing protocol, and it's what the whole session is about.

There are two families of routing protocol, and the dad's list names one of each. OSPF has every router share its piece of the map until everyone holds the same map. BGP has neighbors tell each other what they can reach, and nobody ever sees the whole picture. One is built for inside a company. The other is built for the internet, and it turns out to be what you want inside a very large building too.

How this page works

  • Same format: short text, a widget, quick checks, interview questions I ask out loud. New terms are underlined and in the Glossary.
  • Nothing to install. The widgets are small networks you can break and watch heal, or fail to heal.
  • Routers talk to each other using the same envelopes as everything else. OSPF messages ride directly on IP; BGP messages ride on TCP. New letters, same envelopes.

The one idea for today. A routing protocol is routers gossiping. The two protocols differ only in what they gossip about: OSPF routers describe their own links so everyone can draw the same map; BGP routers describe what they can reach so the next neighbor can decide for itself. Everything else is detail.

The map problem

A router that just booted knows exactly one thing: the networks on its own ports. Those are its connected routes, and they appear in the table on their own. For any other destination it needs an entry, and somebody has to put it there.

Typing it in

A static route is an entry a person typed: "to reach 10.3.0.0/24, send to R3." It works, and small networks run on them. The most common static route in the world is the default route, written 0.0.0.0/0: "anything I don't have a better entry for goes this way," usually toward the internet. Your home router has exactly one route worth mentioning, and it's that one.

Static routes have two problems. They don't scale: thirty routers and a hundred networks is three thousand entries to type and keep consistent. And they don't react: if a link dies, the entry still points at it, and packets go into the hole until a human fixes it. A typo is worse than a hole. If R1 says "C is via R2" and R2 says "C is via R1," a packet bounces between them until its TTL hits zero. That's a routing loop, and it's exactly why TTL exists.

Interview questions

I ask, you answer out loud, one to two minutes. Then we open the answer together.

Interview question

How does a router know where to send a packet for a network it isn't attached to?

What a strong answer covers
  • It looks the destination up in its routing table and picks the most specific matching entry, which names a next-hop router or an outgoing port.
  • Entries come from three places: directly connected networks, static routes typed by an admin, and routing protocols where routers tell each other.
  • If nothing matches, the default route catches it; if there's no default either, the packet is dropped and the sender gets an ICMP unreachable.
  • Strong answers name OSPF and BGP as the two protocol families and say roughly where each lives.

Follow-up: A packet arrives for a network the router has no route to at all. What does it do? (Drop it and send ICMP destination unreachable back to the source. Routers never guess.)

Interview question

What's a default route, and when would you use one instead of a routing protocol?

What a strong answer covers
  • 0.0.0.0/0: matches everything, used only when nothing more specific matches.
  • Use it wherever there's only one way out: a home router toward its ISP, a branch office with one link to headquarters, a server with one gateway.
  • A routing protocol earns its complexity only when there are multiple paths that can change. One exit, no protocol needed.
  • Bonus: even networks that run OSPF or BGP usually carry a default route at the edge for "the rest of the internet."

Follow-up: Your laptop's table has a connected route for 192.168.1.0/24 and a default route. Why doesn't it need anything else? (Everything is either local, handled by ARP, or far, handled by the gateway. Two entries cover the world.)

Interview question

Two routers each believe the other is the way to some network. What happens to a packet, and what stops it?

What a strong answer covers
  • A routing loop: the packet bounces between them, each hop rewriting the Ethernet envelope and lowering TTL.
  • TTL reaches zero, the packet is dropped, and the router that dropped it sends ICMP time exceeded to the source. That's also how traceroute works.
  • Causes: a static route typo, or a routing protocol mid-update (transient loops happen for a second or two after a change).
  • Fix: correct the entries, or let the protocol converge. Loops eat bandwidth on the affected link while they last.

Follow-up: How would you spot a loop from the outside? (traceroute shows the same two hops alternating; interface counters on that link spike.)

OSPF: everyone shares the map

OSPF is the routing protocol most companies run inside their own network. The idea fits in a sentence: every router tells every other router about its own links, so everyone ends up holding the same map, and each one works out its own best paths from that map.

How it works

  1. Find the neighbors. Each router sends small hello messages out every port. Routers that hear each other become neighbors and keep saying hello every few seconds. Silence for long enough means the link is dead.
  2. Describe your links. Each router writes down "I am R1, I have a link to R2 with cost 1 and a link to R3 with cost 3" and sends it to its neighbors, who pass it on. This spreading is called flooding. Within seconds every router has everyone's description.
  3. Draw the map. Put all the descriptions together and you have the whole network: every router, every link, every cost. Every router holds an identical copy.
  4. Find the shortest paths. Each router runs a shortest-path calculation from itself to every destination, adding up link costs. The results go straight into its routing table.

Cost is a number on each link, lower is better, set from the link's speed by default: a 10 Gb link costs less than a 1 Gb link. So "shortest" means cheapest, not fewest hops. Three fast hops beat one slow one.

When something breaks

The two routers on a dead link stop hearing hellos, update their own descriptions, and flood the news. Everyone edits their map and recomputes. The whole thing, called convergence, takes seconds, and no human is involved. That's the entire reason to run a routing protocol.

Two more words for the interview. Big networks split the map into areas so no router has to hold everything; area 0 is the backbone that connects the others. And OSPF is an interior gateway protocol, an IGP: it runs inside one organization, because sharing your whole map with strangers is not something anyone would do. You'll also hear IS-IS, a sibling protocol that works the same way and is common in very large carriers.

Interview questions

Out loud, one to two minutes each.

Interview question

Explain how OSPF works to someone who already knows what a routing table is.

What a strong answer covers
  • Routers discover neighbors with hellos, then each describes its own links and costs and floods that to everyone.
  • Every router assembles the same map of the whole area from those descriptions.
  • Each router runs a shortest-path calculation from itself (Dijkstra, if they want the name) and installs the results in its table.
  • Link-state protocol, interior use, cost based on link speed, areas for scale, fast convergence.

Follow-up: Why do all the routers need the same map? (So they all agree on the same paths. If two routers computed from different maps, packets could loop.)

Interview question

A link fails in an OSPF network. Walk me through what happens, step by step, and roughly how long it takes.

What a strong answer covers
  • The routers at each end stop receiving hellos (or see the port go down) and declare the neighbor dead.
  • Each updates its own link description and floods it; every router receives the update.
  • Every router removes the link from its map and recomputes shortest paths; tables update.
  • Seconds, typically. During those seconds there can be brief loops or drops, which is why fast detection matters.

Follow-up: What if the link comes back but keeps flapping up and down? (Every flap floods and recomputes network-wide. Real networks damp flapping links or shut them down.)

Interview question

What does "cost" mean in OSPF, and how would you use it to steer traffic?

What a strong answer covers
  • A number per link, lower is better, derived from bandwidth by default so faster links are preferred.
  • The path chosen is the lowest sum of costs, not the fewest hops.
  • Admins set costs by hand to steer traffic: raise the cost of a link you want to keep as backup, lower it to attract traffic.
  • Bonus: equal-cost paths get traffic split across them (ECMP), which the data center tab uses heavily.

Follow-up: In the widget, what single cost change would make A prefer the path through D directly from B? (Lower B to D from 4 to 1: then A, B, D, E costs 3 and beats A, B, C, D, E at 4.)

BGP: neighbors trade what they can reach

The internet is about seventy-five thousand separate networks: ISPs, universities, companies, Meta. Each is an autonomous system with its own number, its own routers, and its own management. Nobody would hand strangers a map of their inside, and nobody could hold a map of all of it anyway. So the protocol that connects them works differently.

How it works

BGP routers form relationships with specific neighbors, called peers, usually across a direct link between two networks. Then each one tells its peers what it can reach: "I can get to 157.240.0.0/16." Every time an announcement passes from one network to the next, the network adds its own number to the front, so the announcement carries the whole path it has traveled: "157.240.0.0/16, path 400 300 100." That list is the AS path, and it's why BGP is called a path-vector protocol. No map, just a growing list of who the route went through.

Choosing

A router usually hears about the same addresses from several peers. The default tie-breaker is the shortest AS path. But before that comes policy: a network can mark routes from a preferred peer with a higher local preference, and local preference wins over path length. Preferred usually means cheaper, or a paying customer. BGP is the only routing protocol where the contracts matter, and that's by design: an ISP won't carry traffic between two other ISPs for free, so it simply doesn't announce their routes to each other.

When something breaks

If a route goes away, the peer sends a withdrawal, and the news ripples outward the same way the announcement did. Convergence across the internet takes tens of seconds to minutes, not seconds, and the internet is never fully settled; somewhere, routes are always changing. BGP runs over TCP on port 179, so peers get reliable delivery for free. Between two different networks it's called eBGP; inside one network, carrying the routes between that network's own routers, it's iBGP. Same protocol, two jobs.

One more thing worth a sentence: because BGP trusts what peers say, a network that announces addresses it doesn't own can pull the world's traffic toward itself. That's a route hijack when it's deliberate and a route leak when it's a mistake, and both make the news every year or two.

Interview questions

Out loud, one to two minutes each.

Interview question

OSPF versus BGP: what's the difference, and where is each one used?

What a strong answer covers
  • OSPF: link-state. Everyone shares their links, everyone holds the same map, each computes shortest paths by cost. Fast convergence. Inside one organization.
  • BGP: path-vector. Peers announce what they can reach with the AS path attached; each router picks by policy, then path length. No shared map. Between organizations, and inside very large ones.
  • OSPF trusts everyone in the area; BGP assumes you might not trust your neighbor and gives you knobs.
  • Transport: OSPF directly on IP, BGP on TCP 179.

Follow-up: Could you run OSPF between two ISPs? (Technically, but neither would hand the other its whole internal map, and there's no way to express "prefer my customer's route." That's why BGP exists.)

Interview question

A BGP router has two routes to the same prefix. How does it choose?

What a strong answer covers
  • Policy first: the route with the higher local preference wins, however long its path.
  • Then the shorter AS path.
  • Then a chain of further tie-breakers (origin, MED, external before internal, and finally the lowest neighbor address) that you can name as "a fixed list of tie-breakers" without reciting.
  • Strong answers give the widget's example: the longer path via the cheaper provider wins once local preference is set.

Follow-up: Why would an ISP deliberately prefer a longer path? (It's a paying customer's route, or the shorter path crosses a peer that charges for transit. Business, not geometry.)

Interview question

What's a BGP route hijack, and why is it possible?

What a strong answer covers
  • A network announces address space it doesn't own, or a more specific piece of someone else's, and the rest of the internet routes that traffic to it.
  • Possible because BGP was built on trust: peers believe what they're told and pass it on.
  • More specific prefixes win (next tab), so announcing a /24 out of someone's /16 pulls all of that /24's traffic.
  • Defenses: filtering what you accept from each peer, and RPKI, a system for checking that an announcement is authorized. Name them, no depth needed.

Follow-up: A mistake and an attack look the same on the wire. How do operators tell? (They often can't at first; what matters is that filters stop both. Most famous incidents were mistakes.)

BGP inside the building

If OSPF is for inside and BGP is for between, why does Meta run BGP between every switch in its data centers? Because a data center isn't a company network. It's thousands of switches, tens of thousands of links, and traffic patterns that change by the hour. At that size the two protocols' trade-offs flip.

Why BGP wins at scale

  • No shared map. With OSPF every switch would hold and recompute a map of thousands of nodes. With BGP each switch only knows what its neighbors told it. Less memory, less work, and a failure only ripples as far as it needs to.
  • Simple to reason about. Each switch gets its own AS number and peers with the switches physically connected to it. If you want to know why traffic went somewhere, you follow the announcements hop by hop. There's no hidden map to consult.
  • Policy per link. Draining a switch for maintenance, steering traffic away from a hot link, keeping one rack's traffic off another's path: all of it is a BGP policy on one neighbor, not a network-wide change.
  • One protocol everywhere. Meta's network team already runs BGP to the internet. Running it inside too means one protocol to learn, monitor, automate, and debug. Meta published this design years ago, and most large data centers followed.

The physical shape this runs on is called spine-leaf: every rack's switch (a leaf) connects to every one of a set of core switches (spines), so any two racks are exactly two hops apart with many equal-cost paths between them. BGP announces each rack's addresses up to the spines, the spines announce them back down, and traffic spreads across all the equal paths at once. That's ECMP, equal-cost multipath, and it's next session's subject.

The rule every router uses

Whatever protocol filled the table, the lookup works the same way. Several entries can match one address: a default route matches everything, a /8 matches a whole company, a /24 matches one rack. The router picks the most specific entry, the one with the longest prefix. This is longest prefix match, and it's why a default route never gets in the way of a real route: it has the shortest prefix of all, so it only wins when nothing else matches.

Two consequences worth saying out loud. Inside a data center, the /24 for a rack beats the /16 for the pod, so traffic goes straight to the right rack. And on the internet, announcing a more specific prefix than the owner does pulls the traffic your way, which is the mechanism behind both traffic engineering and hijacks.

Interview questions

Out loud, one to two minutes each. The first one is a Meta favorite.

Interview question

Why would a data center run BGP between its switches instead of OSPF?

What a strong answer covers
  • Scale: OSPF needs every device to hold and recompute a full map; with thousands of switches that's heavy and failures ripple everywhere. BGP keeps knowledge local to neighbors.
  • Operability: one AS per switch or rack, peering over direct links, so any path can be explained by following announcements. Draining or steering is a policy on one link.
  • One protocol inside and outside, which simplifies tooling and automation.
  • Spine-leaf with ECMP is the topology it runs on. Meta published the design (its fabric) and it became the standard.

Follow-up: What's the cost of that choice? (More configuration: every neighbor relationship is explicit, so automation is mandatory. Convergence can be slower than a tuned OSPF unless you tune BGP timers too.)

Interview question

A router has 0.0.0.0/0, 10.0.0.0/8, and 10.1.4.0/24 in its table. A packet for 10.1.4.9 arrives, then one for 10.7.0.1, then one for 8.8.8.8. Which route does each take, and why?

What a strong answer covers
  • 10.1.4.9 matches all three; the /24 is the most specific, so it wins.
  • 10.7.0.1 matches the default and the /8; the /8 wins.
  • 8.8.8.8 matches only the default route, so that's the one.
  • The principle: longest prefix match, always, regardless of which protocol installed the entries or their order.

Follow-up: Where does this show up in a BGP hijack? (Announcing a /24 inside someone's /16 wins the lookup everywhere it's accepted, so the traffic for that /24 comes to you.)

Interview question

You're asked to pick a routing protocol for three networks: a campus with twenty routers, a company connecting to two ISPs, and a data center with three thousand switches. What do you pick for each, and why?

What a strong answer covers
  • Campus: OSPF (or IS-IS). One organization, a map that fits comfortably, fast convergence, no policy needed.
  • Two ISPs: BGP at the edge, because you need to exchange routes with other organizations and to prefer one link over the other by policy. OSPF inside still.
  • Data center: BGP between switches, for the scale and per-link control reasons, on a spine-leaf fabric with ECMP.
  • Strong answers say the choice is about trust boundaries and scale, not about which protocol is "better."

Follow-up: The company with two ISPs wants traffic to leave via ISP A but come back via either. Which BGP knob handles the outbound choice? (Local preference on routes learned from A.)

Practice

Out loud first, then open the answer.

1. Where do routing table entries come from?

Three places: networks connected to the router's own ports, static routes a person typed (including the default route), and routing protocols where routers tell each other. Whatever the source, the lookup picks the most specific match.

2. OSPF in three sentences.

Every router describes its own links and costs and floods that to everyone. Everyone assembles the same map and computes its own shortest paths by total cost. When a link fails, the news floods and everyone recomputes in seconds.

3. BGP in three sentences.

Each network tells its peers which addresses it can reach, and every hop adds its own AS number to the path. A router with several routes to the same addresses picks by policy first, then shortest AS path. It's how the internet's networks connect without anyone sharing a map.

4. Why does a data center run BGP inside?

Thousands of switches make a shared map heavy. BGP keeps knowledge local, lets you explain any path by following announcements, gives policy per link for draining and steering, and it's the same protocol already used at the edge. It runs on spine-leaf with equal-cost paths.

5. Explain longest prefix match with an example.

A packet for 10.1.4.9 matches 0.0.0.0/0, 10.0.0.0/8, and 10.1.4.0/24. The router uses the /24 because it's the most specific. The default route only wins when nothing else matches at all.

6. A link dies. What's different about how OSPF and BGP recover?

OSPF: the routers on the link notice within seconds, flood the change, and every router recomputes; seconds. BGP: the peer withdraws the affected routes, the withdrawal ripples hop by hop, and each router falls back to its next-best route; tens of seconds to minutes across the internet.

Paper problems

a. In the OSPF widget's network, find A's cheapest path to E by hand, then again with the C to D link removed.

A, B, C, D, E: 1 + 1 + 1 + 1 = 4. Alternatives: A, C, D, E costs 5; A, B, D, E costs 6; A, C, E costs 8. Without C to D: A, B, D, E at 6 beats A, B, C, E at 7 and A, C, E at 8. Check both in the widget.

b. A router hears 157.240.0.0/16 from peer X with path "200 100" and from peer Y with path "400 300 100." No policy. Which wins? Now the admin sets local preference 200 on everything from Y. Which wins?

No policy: X, shorter AS path (2 versus 3). With local preference 200 on Y's routes (default is 100): Y, because local preference is checked before path length. Same as the widget's policy toggle.

c. Routes: 0.0.0.0/0, 10.0.0.0/8, 10.1.0.0/16, 10.1.4.0/24, 10.1.4.128/25. Which route for 10.1.4.130, for 10.1.4.10, for 10.1.200.7, for 10.9.9.9, for 1.1.1.1?

10.1.4.130: the /25 (128 to 255). 10.1.4.10: the /24. 10.1.200.7: the /16. 10.9.9.9: the /8. 1.1.1.1: the default. Most specific match every time.

d. A BGP router receives an announcement whose AS path already contains its own AS number. What does it do, and why?

It rejects the route. Its own number in the path means the announcement already went through it once; accepting it would create a loop. This is how BGP prevents loops without a map: the path is the loop detector.

e. Which protocol for each: a hospital with twelve routers; a company with two internet providers; a cloud region with 4,000 switches; a home network.

Hospital: OSPF. Two providers: BGP at the edge (OSPF inside). Cloud region: BGP on spine-leaf. Home: none, a single default route to the ISP.

Narration rubric: how routers learn the map

  • Said the three sources of table entries: connected, static, protocols.
  • Said what a default route is and why it's last resort.
  • OSPF: hellos, each router describes its links, flooding, everyone holds the same map, shortest path by cost.
  • OSPF failure: detect, flood, recompute, seconds.
  • BGP: autonomous systems with numbers, peers, announcements with the AS path growing per hop.
  • BGP choice: local preference first, then shortest AS path.
  • BGP failure: withdrawals ripple, fall back to next best, slower than OSPF.
  • Said where each is used, including BGP inside large data centers, and one reason why.
  • Explained longest prefix match with a concrete example.
  • Named TCP 179 for BGP and that OSPF rides directly on IP.

  • 2. Be the router, in Python

    Two small functions, both things you've seen this session.

    OSPF side: write shortest_paths(graph, start) that takes the widget's network as a dictionary of links and costs and returns the cheapest cost and path from start to every other router.     BGP side: write choose_route(routes) where each route is a dictionary with a path (list of AS numbers) and a local_pref (default 100). Then add a check that rejects any route whose path contains your own AS number.
