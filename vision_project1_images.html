Set up the project

A new folder and notebook. Almost nothing to download.

  1. Create a folder called tennis-vision.
  2. Create a notebook inside it called vision_project1.ipynb.
  3. The digits dataset ships with scikit-learn, so there is no data file to fetch.
  4. Save one tennis photo from the web into the folder as court.jpg, you will need it in section 6.

Cell 1 · imports and load

import numpy as np
import matplotlib.pyplot as plt
from PIL import Image
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, confusion_matrix

digits = load_digits()
print("images:", digits.images.shape)
print("flat:  ", digits.data.shape)

You should see

images: (1797, 8, 8) and flat: (1797, 64). Same 1797 images, stored two ways: as grids and as flattened rows.

Structure your notebook with these sections, the same habit as the tennis project: 1. Load, 2. Explore, 3. Image math, 4. Classify, 5. Inspect, 6. Real photo pipeline, 7. The scramble test.

Build and display the average image for the digit 3, then count how many images there are of each digit.

Section 3: image math

Editing an image is arithmetic on the array.

Task A · four operations at once

Take image 0 and produce a brighter version, an inverted version, a left-right flip, and a middle 4 by 4 crop. Display all five side by side.

Solution
img = digits.images[0]
brighter = np.clip(img + 4, 0, 16)
inverted = 16 - img
flipped  = np.fliplr(img)
cropped  = img[2:6, 2:6]

fig, axes = plt.subplots(1, 5, figsize=(10, 2))
for ax, picture, name in zip(axes,
        [img, brighter, inverted, flipped, cropped],
        ["original", "brighter", "inverted", "flipped", "cropped"]):
    ax.imshow(picture, cmap="gray"); ax.set_title(name, fontsize=9); ax.axis("off")
plt.show()

You should see

Five versions of the same digit. The cropped one is visibly smaller, (4, 4) instead of (8, 8).

Task B · a darker version

Subtract 4 from every pixel of image 0, clipped so nothing goes below 0, and display it next to the original.

Solution
darker = np.clip(digits.images[0] - 4, 0, 16)
fig, axes = plt.subplots(1, 2, figsize=(4, 2))
axes[0].imshow(digits.images[0], cmap="gray"); axes[0].set_title("original"); axes[0].axis("off")
axes[1].imshow(darker, cmap="gray"); axes[1].set_title("darker"); axes[1].axis("off")
plt.show()

You should see

The same digit, dimmer. Without np.clip the values could go negative and the display would look wrong.

Task C · flip up and down

Flip image 0 upside down and confirm in code that the result really differs from the original.

Solution
upside = np.flipud(digits.images[0])
print("changed:", not np.array_equal(upside, digits.images[0]))
plt.imshow(upside, cmap="gray"); plt.axis("off"); plt.show()

You should see

changed: True and an upside-down digit. These operations are the basis of data augmentation, which we may need for tennis.

Section 4: classify

Your first computer vision model, using tools you already know.

Task A · split and train

Split into train and test (25% test), then train a logistic regression on the flattened images and print its accuracy.

Solution
X, y = digits.data, digits.target
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25, random_state=42)

model = LogisticRegression(max_iter=5000).fit(X_train, y_train)
print("accuracy:", round(accuracy_score(y_test, model.predict(X_test)), 4))

You should see

About 0.9733. Your first vision model, 97% accurate, from the same logistic regression you used on tennis.

Task B · test normalization honestly

Train a second logistic regression on pixels divided by 16 (scaled to 0 to 1) and compare accuracies. Does normalizing help here?

Solution
norm = LogisticRegression(max_iter=5000).fit(X_train / 16.0, y_train)
print("raw:       ", round(accuracy_score(y_test, model.predict(X_test)), 4))
print("normalized:", round(accuracy_score(y_test, norm.predict(X_test / 16.0)), 4))

You should see

Raw about 0.9733, normalized about 0.9667. Normalizing is slightly worse here, because these pixels already sit in a small range. It becomes important for real photos and neural networks. Same habit as tennis: test, do not assume.

Task C · compare four models

Train logistic regression, a neural net, KNN, and a decision tree, and print all four accuracies.

Solution
from sklearn.neural_network import MLPClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier

models = {
    "logistic regression": LogisticRegression(max_iter=5000),
    "neural net": MLPClassifier(hidden_layer_sizes=(64,), max_iter=1000, random_state=42),
    "KNN": KNeighborsClassifier(n_neighbors=3),
    "decision tree": DecisionTreeClassifier(random_state=42),
}
for name, m in models.items():
    m.fit(X_train, y_train)
    print(f"{name:22} {accuracy_score(y_test, m.predict(X_test)):.4f}")

You should see

Roughly KNN 0.987, neural net 0.982, logistic regression 0.973, decision tree 0.858. Unlike tennis, the models really do separate here.

Section 5: inspect

Look at the mistakes, then look inside the model.

Task A · confusion matrix and errors

Print the confusion matrix and the number of wrong predictions, then display the first four misclassified images with true and predicted labels.

Solution
pred = model.predict(X_test)
print(confusion_matrix(y_test, pred))
print("wrong:", (pred != y_test).sum(), "of", len(y_test))

wrong = np.where(pred != y_test)[0]
fig, axes = plt.subplots(1, 4, figsize=(7, 2))
for ax, idx in zip(axes, wrong[:4]):
    ax.imshow(X_test[idx].reshape(8, 8), cmap="gray")
    ax.set_title(f"is {y_test[idx]}, said {pred[idx]}", fontsize=9)
    ax.axis("off")
plt.show()

You should see

A strong diagonal, about 12 wrong out of 450, and four genuinely messy digits.

Task B · see what the model learned

Print the shape of the model's coefficients, then reshape them into 8 by 8 images and display the maps for digits 0 through 4.

Solution
print("coefficient shape:", model.coef_.shape)

fig, axes = plt.subplots(1, 5, figsize=(9, 2))
for ax, i in zip(axes, range(5)):
    ax.imshow(model.coef_[i].reshape(8, 8), cmap="RdBu")
    ax.set_title(f"digit {i}", fontsize=9); ax.axis("off")
plt.show()

You should see

(10, 64), one weight per pixel per digit, and five evidence maps. Red pixels push toward that digit, blue push away. The map for 0 shows a ring.

Task C · predict a single image

Predict just test image 0 and print the prediction next to the true label.

Solution
one = X_test[0].reshape(1, -1)
print("predicted:", model.predict(one)[0], " actual:", y_test[0])

You should see

A matching pair. reshape(1, -1) is needed because predict expects a table of rows, not a single row.

Section 6: the real photo pipeline

The part that matters most for tennis. Use the court.jpg you saved.

Before you start: make sure a tennis photo is saved in your project folder as court.jpg. Any match photo works.

Task A · load it

Open the photo with Pillow, print its size and mode, convert it to an array, and print the array shape and value range. Display it.

Solution
img = Image.open("court.jpg")
print("size (width, height):", img.size)
print("mode:", img.mode)

arr = np.array(img)
print("array shape:", arr.shape)
print("value range:", arr.min(), "to", arr.max())
plt.imshow(arr); plt.axis("off"); plt.show()

You should see

A shape like (height, width, 3) and a range up to 255. The trailing 3 is the red, green, and blue channels, and the range is 0 to 255, not 0 to 16 like the digits.

Task B · prepare it

Resize the photo to 64 by 64, convert a copy to grayscale, normalize the resized version to 0 to 1, and flatten it. Print the shape or length at each step.

Solution
small_arr = np.array(img.resize((64, 64)))
print("resized:", small_arr.shape, " total numbers:", small_arr.size)

gray = np.array(img.convert("L"))
print("grayscale:", gray.shape)

normalized = small_arr / 255.0
print("normalized range:", round(float(normalized.min()), 3), "to", round(float(normalized.max()), 3))

flat = small_arr.reshape(-1)
print("flattened length:", flat.shape[0])

You should see

Resized (64, 64, 3) holding 12288 numbers, grayscale with no third dimension, a normalized range inside 0 to 1, and a flattened length of 12288. Compare that to 64 numbers per digit.

Task C · the color channels, and the surface preview

Display the red, green, and blue channels separately as grayscale images, then print the average R, G, B of the top half and the bottom half of the photo.

Solution
fig, axes = plt.subplots(1, 3, figsize=(9, 3))
for ax, i, name in zip(axes, [0, 1, 2], ["red", "green", "blue"]):
    ax.imshow(arr[:, :, i], cmap="gray"); ax.set_title(name); ax.axis("off")
plt.show()

top    = arr[:arr.shape[0]//2]
bottom = arr[arr.shape[0]//2:]
print("top    average R,G,B:", [int(v) for v in top.mean(axis=(0, 1))])
print("bottom average R,G,B:", [int(v) for v in bottom.mean(axis=(0, 1))])

You should see

Three channel images, and two sets of average colors. On a clay photo the red average runs high; on grass the green does. That single difference is the core signal the surface classifier will use, which is a good sign the project is learnable.

Section 7: the scramble test

The experiment that shows why the next lesson exists.

Task A · scramble the pixels

Apply one fixed random pixel permutation to every image, retrain, and compare accuracy to normal.

Solution
rng = np.random.default_rng(0)
perm = rng.permutation(64)

X_train_s, X_test_s = X_train[:, perm], X_test[:, perm]
scrambled = LogisticRegression(max_iter=5000).fit(X_train_s, y_train)

print("normal:   ", round(accuracy_score(y_test, model.predict(X_test)), 4))
print("scrambled:", round(accuracy_score(y_test, scrambled.predict(X_test_s)), 4))

You should see

Both 0.9733, identical. The model has no idea where the pixels are, so scrambling them changes nothing.

Task B · see what the model sees

Display a normal digit next to its scrambled version.

Solution
fig, axes = plt.subplots(1, 2, figsize=(4, 2))
axes[0].imshow(X_test[0].reshape(8, 8), cmap="gray"); axes[0].set_title("normal"); axes[0].axis("off")
axes[1].imshow(X_test[0][perm].reshape(8, 8), cmap="gray"); axes[1].set_title("scrambled"); axes[1].axis("off")
plt.show()

You should see

The scrambled one is unreadable to you, yet the model scores exactly the same on it. That gap is why convolutional networks exist.

Task C · the size problem

Print how many features a flattened image has at 8 by 8 grayscale, 64 by 64 color, and 224 by 224 color.

Solution
print("8x8 gray:     ", 8 * 8)
print("64x64 color:  ", 64 * 64 * 3)
print("224x224 color:", 224 * 224 * 3)

You should see

64, 12288, then 150528. Classic models buckle at that many inputs, which is the other reason CNNs exist.
