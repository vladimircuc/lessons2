Charts I: bars and histograms

You can plot straight from a DataFrame. A picture shows the shape of the data far faster than a table of numbers.

How plotting works here. pandas has a built-in .plot() that draws charts using matplotlib under the hood. You pick the chart type with kind="bar", "hist", "line", and so on. In a notebook the chart appears right under the cell. We also use plt (matplotlib) to add a title and axis labels.

Cell · a bar chart of matches per surface

df["surface"].value_counts().plot(kind="bar", title="Matches per surface")
plt.ylabel("number of matches")
plt.show()

value_counts() gives the count per surface (same as week 1), and .plot(kind="bar") turns that into bars. You will see Hard towering over Clay and Grass, which matches the real tour calendar.

Cell · a histogram of match length

df["minutes"].plot(kind="hist", bins=30, title="How long matches last")
plt.xlabel("minutes")
plt.show()

A histogram splits a number column into ranges (bins) and shows how many matches fall in each. bins=30 sets how fine the buckets are. You see most matches cluster around 90 to 120 minutes with a long tail of marathons.

Two habits: always add a title so a chart explains itself, and call plt.show() at the end of the cell to render it cleanly (it also hides a line of text output pandas would otherwise print).

The winner/loser trap, and the fix

This is the most important idea in the whole project. Get it right and everything downstream works. Get it wrong and your model is meaningless.

The trap. Our data lists every match as winner_... and loser_.... The winner is always the winner. If we ask a model "given this row, who won?", the answer is baked into the column names, there is nothing to predict. Even the difference features you built last week secretly point at the answer, because they are always computed as winner minus loser. A model trained on that learns a useless rule and falls apart on a real, unplayed match.
The fix: player A vs player B, chosen at random.

Instead of "winner" and "loser", we relabel the two players as player A and player B. For each match we flip a coin: sometimes the winner is A, sometimes the winner is B. Then we make a target column that is 1 when A won and 0 when B won. Because the coin flip is random, A wins about half the time, so the target is balanced and the model cannot cheat by always guessing one side. It is forced to look at the features (the ranking gap, and so on) to decide. Our features become "player A minus player B", computed from whoever ended up as A.

Cell · flip the coin and make the target

rng = np.random.default_rng(42)   # fixed seed so results repeat

# for each match, randomly decide whether the winner is player A
df["winner_is_A"] = rng.random(len(df)) < 0.5

# target: 1 if player A won, 0 if player B won
df["target"] = df["winner_is_A"].astype(int)

df["target"].value_counts()

You should see roughly equal counts of 1 and 0. That balance is the whole point: the model starts from a coin flip and has to earn its accuracy from the features.

Cell · build the features from A and B

# helper: player A's value minus player B's value, based on who is A
def a_minus_b(winner_col, loser_col):
    a = np.where(df["winner_is_A"], df[winner_col], df[loser_col])  # A's value
    b = np.where(df["winner_is_A"], df[loser_col], df[winner_col])  # B's value
    return a - b

df["rank_diff"]   = a_minus_b("winner_rank", "loser_rank")
df["points_diff"] = a_minus_b("winner_rank_points", "loser_rank_points")
df["age_diff"]    = a_minus_b("winner_age", "loser_age")
df["height_diff"] = a_minus_b("winner_ht", "loser_ht")

df[["target", "rank_diff", "points_diff", "age_diff", "height_diff"]].head()

np.where(condition, x, y) picks x where the condition is True and y where it is False. So for each match it grabs A's value and B's value correctly depending on the coin flip, then subtracts. Now the features describe A relative to B, with no hint of who won.

Sanity check it learned nothing yet. Because A is random, rank_diff is now positive or negative roughly equally. The signal is still there (when A is much stronger, A usually wins), but the model has to discover the direction. That is exactly what we want.

3.In a comment, explain in your own words why we randomize who is player A instead of always making the winner player A.

Solution

If the winner were always player A, the target would always be 1, and the model would just learn "A always wins", which predicts nothing for a new match. Randomizing makes the target a real 50/50 question, so the model must use the features to decide, and its accuracy becomes meaningful.

Splitting into train and test

To know if a model is any good, you have to test it on matches it has never seen. So we hold some out.

Why split at all. If you train and test on the same matches, of course the model looks great, it already saw the answers. That tells you nothing about new matches. So we teach the model on one slice of the data (the training set) and check it on a separate slice it never saw (the test set). The test accuracy is the honest measure of how well it predicts.

Why split by time for tennis. A random split is fine in general, but for anything with time, predicting the future from the past is the honest test. So we train on the earlier matches of 2023 and test on the later ones. That mirrors real life: you would use past results to predict an upcoming match, never the reverse.

Cell · a time-based 80/20 split

df_sorted = df.sort_values("tourney_date")   # oldest matches first

cutoff = int(len(df_sorted) * 0.8)           # 80% mark
train = df_sorted.iloc[:cutoff]              # earlier matches
test  = df_sorted.iloc[cutoff:]              # later matches

print("train:", train.shape[0], " test:", test.shape[0])

Sort by date, find the 80% point, take everything before it as training and everything after as testing. The model will learn on early-season matches and be judged on late-season ones it has never seen.

Cell · the simpler random split (for comparison)

train_r = df.sample(frac=0.8, random_state=42)   # random 80%
test_r  = df.drop(train_r.index)                 # the other 20%
print(train_r.shape[0], test_r.shape[0])

sample grabs a random 80%, and drop(train_r.index) keeps the rows that were not chosen. Good to know, but for our tennis predictor we will use the time-based split above.

3.In a comment, explain why testing on future matches is more honest than a random split for this project.

Solution

In real use you always predict an upcoming match from past data. A time split copies that exactly, so the test accuracy reflects real-world performance. A random split lets the model train on some late matches and test on earlier ones, which is a mild form of peeking at the future.

The baseline: the number to beat

Before building anything fancy, measure the dumbest reasonable predictor. That is the bar your real model has to clear.

What a baseline is and why it matters. A baseline is the simplest rule you could use without any machine learning. For tennis, that rule is "the higher-ranked player wins". If a fancy model cannot beat that simple rule, the model is not worth much. Measuring the baseline first keeps you honest: it turns "my model is 65% accurate" into "my model is 65%, and the free baseline was already 64%", which is a very different story.

Cell · measure the favorite-wins baseline on the test set

df_sorted = df.sort_values("tourney_date")
cutoff = int(len(df_sorted) * 0.8)
test = df_sorted.iloc[cutoff:]

# rule: predict A wins when A is the higher-ranked player.
# rank_diff is A_rank - B_rank, and a smaller rank number is better,
# so A is the favorite when rank_diff is negative.
baseline_pred = (test["rank_diff"] < 0).astype(int)

accuracy = (baseline_pred == test["target"]).mean()
print("baseline accuracy:", round(accuracy, 3))

We predict player A wins whenever A is ranked higher, then compare those guesses to the real target and take the share we got right. On the real data this lands around 0.65. Write that number down, it is the score to beat when we train a model next week.

Keep this number in your head. When your first trained model prints its accuracy next week, the first thing you do is compare it to this baseline. Beating it by a few points is a genuine, honest win. Scoring 0.97 would mean something leaked, not that you built a genius.
