Addresses, networks, and the router

Last time: envelopes and delivery inside one network. This time: how a computer reads an address, how it knows whether the destination is nearby, and what happens when it isn't.

Start here

Session 1 ended with a frame arriving at computer B on the same network. Two questions were left hanging. How did A know B was on the same network in the first place? And what happens when it isn't, when B is on the other side of the building or the other side of the world?

Both answers come from the IP address itself, once you know how to read one. So this session starts with reading, moves to a little arithmetic that interviewers love to test, and ends with the device that carries packets between networks: the router.

Reading an IP address

An address like 192.168.1.10 looks like four numbers. To the computer it's one number, 32 bits long. A bit is a single one or zero. Thirty-two ones and zeros in a row is impossible to read, so humans split them into four groups of eight, turn each group into an ordinary number, and put dots between them.

Each group of eight bits is called an octet. Eight bits can make any number from 0 to 255. That's why you'll never see 256 or 300 in an IP address.

Eight light switches

Here's the only piece of binary you need. Picture eight light switches in a row. Each one has a value: 128, 64, 32, 16, 8, 4, 2, 1. The number an octet represents is the sum of the switches that are on. So 192 is 128 + 64, two switches on. And 10 is 8 + 2.

Why this matters

Everything in the next two tabs is about which of the 32 switches describe the network and which describe the computer. You can't see that split in decimal. In binary it's obvious. You won't do much binary in the interview, but you need to see it once so the rest isn't magic.

IPv6, in one paragraph. Everything above is IPv4. There are only about 4.3 billion 32-bit addresses and the world ran out, so IPv6 uses 128 bits and is written in hex, like 2001:db8::1. Same idea, much bigger. You will not be asked to subnet IPv6 this month. Know that it exists, why, and that it looks different.

Network part, host part

An IP address is two things glued together. The front part says which network, like a street name. The back part says which computer on that network, like a house number. Every computer on the same network shares the front part.

Where's the split? That's what the subnet mask tells you. The modern way to write it is a slash and a number: /24 means "the first 24 bits are the network part." The other 8 bits are the host part, host being the networking word for a computer. This slash notation is called CIDR, and a network defined this way is called a subnet.

You'll also see the mask written the old way, as four octets: 255.255.255.0. It means the same thing as /24. Each 255 is an octet with all eight switches on, saying "this whole octet is network." The 0 says "this whole octet is host."

So 192.168.1.10/24 reads: network 192.168.1, host 10. Anyone whose address starts with 192.168.1 is on this network and can be reached directly, the way you saw in session 1.

Two addresses you can't give to a computer

Every subnet has two special addresses. The one with all host bits set to zero is the network address: it's the name of the network itself, 192.168.1.0 here. The one with all host bits set to one is the broadcast address, 192.168.1.255: a packet sent there goes to every computer on the network. That's the address ARP shouted to in session 1.

Neither can belong to a computer. So a /24 has 256 addresses but only 254 usable ones. Interviewers ask this constantly, and "256" is the wrong answer they're fishing for.

Private addresses. Three ranges are reserved for homes and offices and never appear on the public internet: anything starting 10., anything from 172.16. to 172.31., and anything starting 192.168.. Your home router swaps them for its one public address on the way out, a trick called NAT. For now the takeaway is simpler: if you see 192.168 or 10-something, you're looking at someone's private network.

Subnet math

Networks often get split into smaller ones. A /24 with 254 addresses might be cut into two /25s, or four /26s, or sixteen /28s, so that each team or each rack gets its own. When you do that, the split no longer lands neatly on a dot, and you need a little arithmetic to answer the three questions that always come up: what's the network address, what's the broadcast, how many hosts fit.

The block size trick

You never need to write out the binary. Here's the shortcut that works for every prefix from /25 to /30.

  1. Find the host bits: 32 minus the prefix. For /26 that's 6.
  2. The block size is 2 to that power. 26 = 64. Networks come in blocks of 64 addresses: they start at 0, 64, 128, 192.
  3. Find the block your address falls in. For 192.168.1.100: 100 is between 64 and 127, so the network address is 192.168.1.64.
  4. The broadcast is the last address in the block: 192.168.1.127.
  5. Usable hosts = block size minus 2: 62. First usable .65, last usable .126.

The mask in dotted form is 256 minus the block size in the octet that's being split: 256 minus 64 is 192, so /26 is 255.255.255.192.

Near or far?

Now the question left over from session 1. Before a computer sends anything, it decides: is the destination on my network? It uses its own address and mask to do it.

  1. Take your own address and keep only the network bits. That's your network.
  2. Take the destination address and keep only the network bits, using your mask.
  3. Compare. Same? The destination is nearby: send directly, using ARP to get its MAC, exactly like session 1.
  4. Different? The destination is on another network. You can't reach it directly. Send it to your default gateway instead.

The default gateway is the router's address on your network, usually something like 192.168.1.1. Your laptop was told the gateway address when it joined the network, right along with its IP and mask. Those three things, IP, mask, gateway, are the whole story of how your laptop knows where it is and where to send things it can't deliver itself.

The router

A router is a device with a foot in two or more networks. It has an address on each one. Its whole job is to take packets from one network and pass them into another, one step closer to where they're going. Each step from one router to the next is called a hop.

What a router does with a frame

  1. A frame arrives addressed to the router's MAC. The router's network card keeps it and opens the Ethernet envelope. That envelope is now garbage.
  2. The router reads the IP envelope's "To" line. The address isn't the router's own, and that's fine: routers are allowed to forward.
  3. It looks the address up in its routing table, a list that says "addresses in this range go out that side." It finds the right side.
  4. It lowers a counter on the IP envelope called the TTL by one. TTL starts around 64 and every router subtracts one. If it ever hits zero, the packet is thrown away. This is what stops a packet from circling forever if two routers point at each other by mistake.
  5. It puts the packet in a brand new Ethernet envelope: To the next machine's MAC on the other network (found with ARP over there), From the router's own MAC on that side. And sends it.

The most important sentence in this session. Crossing a router, the Ethernet envelope is thrown away and replaced. The IP envelope keeps the same To and From all the way, only the TTL ticks down. Layer 2 is hop by hop. Layer 3 is end to end. If you remember one line from today, it's that one.

One request across a router

A is on 192.168.1.0/24. B is on 10.0.0.0/24. The router sits between them with one address on each side.

Two things people get wrong

  • A does not ARP for B. B isn't on A's network, so shouting "who has 10.0.0.20?" on A's network gets silence. A ARPs for the gateway, and the router does its own ARP for B on the other side.
  • The router does not change the destination IP. The To line on the IP envelope says 10.0.0.20 when A writes it and still says 10.0.0.20 when B reads it. Only the Ethernet envelopes change, and only the TTL on the IP envelope moves.

Splitting and bundling a switch

Three more words from the interview list, all about switches. None of them is deep. Each one is a single idea with a name.

VLANs: one switch, several rooms

A VLAN splits one physical switch into several separate networks. You tell the switch "ports 1 to 3 are VLAN 10, ports 4 to 6 are VLAN 20," and from then on the two groups can't hear each other at all. A broadcast in VLAN 10 stays in VLAN 10. To get from one VLAN to another, a packet has to go through a router, just like between any two networks. That's the point: it lets you separate the finance team from the guest Wi-Fi without buying a second switch.

Two port words go with this. A port that belongs to one VLAN, where a normal computer plugs in, is an access port. A cable between two switches that has to carry several VLANs at once is a trunk port: every frame crossing it gets a small tag saying which VLAN it belongs to, so the far switch can sort them back out. The tag format is called 802.1Q, and people just say "dot1q."

LACP: several cables, one link

Sometimes one cable between two switches isn't enough bandwidth, or you don't want one cable failing to cut the connection. So you plug in two or four cables and tell both ends to treat them as one logical link. Traffic is spread across them, and if one dies the others carry on. The bundle is called a port channel (or a LAG), and LACP is the protocol the two ends use to agree on the bundle and notice when a cable in it dies. That's the whole thing.

Layer 2 versus layer 3

You'll hear devices described by the layer they work at. A layer 2 device forwards using MAC addresses: that's a switch. A layer 3 device forwards using IP addresses: that's a router. A layer 3 switch does both in one box, switching within a VLAN and routing between VLANs, and most switches in a data center are layer 3 switches. When someone asks "is that an L2 or L3 problem," they're asking "MAC-level or IP-level."

One more size. Session 1 said packets are about 1,500 bytes. The exact limit a link can carry in one frame is its MTU, and 1,500 bytes is the standard Ethernet MTU. A packet bigger than the MTU has to be split or dropped, and mismatched MTUs are a classic source of "small things work, big things hang." Just know the word and the number for now.

Practice

Out loud first, then open the answer. Same as last time.

1. What does 192.168.1.10/24 mean, piece by piece?

The address is 192.168.1.10. The /24 says the first 24 bits, the first three octets, are the network part: 192.168.1. The last octet, 10, is the host part. Every address that starts 192.168.1 is on this network. The network address is 192.168.1.0, the broadcast is 192.168.1.255, and 254 computers can live here.

2. Why does a /24 have 254 usable addresses and not 256?

Two of the 256 are reserved: the network address (all host bits zero) names the network, and the broadcast address (all host bits one) means everyone. Neither can be assigned to a computer.

3. How does a laptop decide whether to send directly or to the gateway?

It keeps the network bits of its own address and of the destination, using its own mask, and compares. If they match, the destination is on the same network: ARP for its MAC and send directly. If not, send the frame to the default gateway's MAC and let the router take it further. The IP envelope still says the real destination either way.

4. What does a router change on a packet, and what does it leave alone?

It throws away the Ethernet envelope and writes a new one for the next cable, with new To and From MACs. It lowers the TTL by one on the IP envelope. It leaves the IP To and From, the TCP envelope, and the letter untouched. Layer 2 is hop by hop; layer 3 is end to end.

5. What is a VLAN for, and what's a trunk?

A VLAN splits one physical switch into separate networks that can't hear each other's traffic, so different groups can share hardware without sharing a network. A trunk is a link between switches that carries several VLANs at once, with an 802.1Q tag on each frame saying which VLAN it belongs to.

6. Tell the trip: A on 192.168.1.10 sends a web request to B on 10.0.0.20.
  1. A's browser writes the request. TCP wraps it for port 80. IP wraps that: To 10.0.0.20, From 192.168.1.10, TTL 64.
  2. A compares network parts: 10.0.0 is not 192.168.1. Far. Send to the gateway, 192.168.1.1.
  3. A ARPs for the gateway's MAC (not B's), then writes the Ethernet envelope To the router's MAC.
  4. The switch delivers the frame to the router's port.
  5. The router opens and discards the Ethernet envelope, reads To 10.0.0.20, finds in its table that 10.0.0.x is on its other side, lowers TTL to 63.
  6. The router ARPs for 10.0.0.20 on that side, writes a new Ethernet envelope To B's MAC, From its own right-side MAC, and sends.
  7. B's network card sees its MAC, opens Ethernet, IP sees its own address, TCP sees port 80, the web server gets the letter.

Quick problems

Do these on paper with the block size trick. Answers hidden below each.

a. Network and broadcast of 10.0.0.77/26

/26 blocks of 64: 0, 64, 128, 192. 77 is in the 64 block. Network 10.0.0.64, broadcast 10.0.0.127, usable .65 to .126 (62 hosts).

b. Are 192.168.1.100 and 192.168.1.140 on the same network with /26?

No. Blocks of 64: 100 is in the 64 to 127 block, 140 is in the 128 to 191 block. Different networks. With /25 (blocks of 128) they'd both be in the 0 to 127 block... except 140 wouldn't. Still no. With /24, yes.

c. How many usable hosts in a /28, and what's the mask?

32 minus 28 is 4 host bits. Block size 16, usable 14. Mask 255.255.255.240 (256 minus 16).

d. You need at least 50 hosts in one subnet. Smallest prefix?

/26 gives 62 usable, enough. /27 gives only 30. So /26.

e. Network and broadcast of 172.16.5.33/27

/27 blocks of 32: 0, 32, 64... 33 is in the 32 block. Network 172.16.5.32, broadcast 172.16.5.63, usable .33 to .62.

Tutor notes (for me)

Pacing for 90 minutes. Start 5, Reading an address 10, Network and host 15, Subnet math 25, Near or far 10, The router 15, Splitting and bundling 10. Subnet math is where the time goes; do three drill questions together on screen before letting her loose on it. If short, compress Splitting and bundling to "one sentence each" and lean on the flashcards.

What "good" looks like in her trip story. The near-or-far comparison comes before any ARP. ARP is for the gateway, not B. The router opens and discards the Ethernet envelope, reads IP, drops TTL, writes a new Ethernet envelope. Destination IP never changes. If she says "layer 2 is hop by hop, layer 3 is end to end" unprompted, she's got it.

The usual confusions. 256 instead of 254. Thinking the router rewrites the destination IP. Thinking A ARPs for B across the router. Confusing the network address with the first usable address. Thinking a VLAN is a physical thing. Each is a two-minute fix when it appears.

Python check. network_info("192.168.1.100/26") should give network 192.168.1.64, broadcast 192.168.1.127, 62 hosts. The clean version: int_ip = (a<<24)|(b<<16)|(c<<8)|d, mask = (0xFFFFFFFF << (32-prefix)) & 0xFFFFFFFF, network = ip & mask, broadcast = network | ~mask & 0xFFFFFFFF. If she uses string splitting on the octets and does the math per octet, that works too but tends to break on prefixes that don't land on an octet boundary; nudge her toward the 32-bit integer.
