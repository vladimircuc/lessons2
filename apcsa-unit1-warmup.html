PART 1

Quick checks

Pick an answer, then click it to see what Java actually does.

01

What value ends up in x?

int x = 7 / 2;
3. Both sides are whole numbers, so Java does integer division and throws the remainder away. It does not round. The .5 is simply deleted.
02

What prints?

System.out.println("Total: " + 5 + 2);
Total: 52. The + operator works left to right. "Total: " + 5 builds the text "Total: 5", and then the 2 gets stuck onto the end of that. Once a String is involved, + means glue, not add. To add first, use parentheses: "Total: " + (5 + 2).
03

What value does (int) 8.97 produce?

8. Casting to int chops off everything after the decimal point. It never rounds, no matter how close the number is to the next one up. If you want 9, that's Math.round.
04

What value ends up in result?

double result = 5 / 2;
2.0. This one catches almost everybody. The division happens first, and 5 / 2 is still int division, so it produces 2. Only afterward does that 2 get stored in a double, which makes it 2.0. Declaring the variable as double does not fix the math, it just changes where the answer lands.
05

Given String word = "computer"; what does word.substring(0, 3) return?

"com". Substring starts at the first index and stops right before the second one. So you get indexes 0, 1, and 2. Handy shortcut: the length of what comes back is always the second number minus the first.
06

After these three lines run, what is count?

int count = 10;
count += 5;
count -= 2;
13. += and -= update the variable in place. count += 5 is just shorthand for count = count + 5. So 10 becomes 15, then 15 becomes 13.
07

Two Strings, a and b. Which line correctly checks whether they hold the same text?

a.equals(b). On Strings, == asks whether the two are the exact same object sitting in the same spot in memory, which is almost never the question you meant to ask. A single = is assignment, and .same() is not a real method.
08

What does Math.pow(2, 3) return?

8.0. It raises the first number to the power of the second, so 2 cubed is 8. The part worth memorizing is that Math.pow always hands back a double, so the value is 8.0 and not 8. That matters the moment you try to store it in an int.
09

Given String name = "Lilah"; which one is a valid way to call toUpperCase?

name.toUpperCase(). toUpperCase belongs to the object, so you put the dot after the variable. Math methods work the opposite way, Math.abs(-4), because you never build a Math object. Knowing which methods go on an object and which go on a class is most of what Unit 1 is testing.
PART 2

Spot the bug

Each of these has exactly one thing wrong. Tell me what it is and how you'd fix it, then reveal.

01

This should print 3.5, but it prints 3.0.

double average = 7 / 2;
System.out.println(average);
Fix 
double average = 7.0 / 2;

One side has to be a decimal or Java sticks with int division. 7.0 / 2 works, and so does (double) 7 / 2. Storing the result in a double is too late, the damage is already done on the right-hand side.

02

This one won't even compile.

int price = 4.99;
Fix 
double price = 4.99;

An int cannot hold a decimal, and Java refuses to quietly throw away part of your number. It makes you say so on purpose. If you genuinely wanted 4, you'd have to write int price = (int) 4.99; so the loss is visible in the code.

03

This is supposed to check whether what was typed matches the answer. Both hold the text "Lilah", but it prints false.

String typed = new String("Lilah");
String correct = "Lilah";
System.out.println(typed == correct);
Fix 
System.out.println(typed.equals(correct));

The two Strings hold identical characters, but they are two separate objects in two separate places. == compares the places, so it says false. .equals() compares the characters, which is what you actually wanted. Use .equals() for text every single time.

04

This should print LILAH, but it prints lilah.

String name = "lilah";
name.toUpperCase();
System.out.println(name);
Fix 
name = name.toUpperCase();

A String can never be changed once it exists. toUpperCase() doesn't edit name, it builds a brand new String and hands it back to you. If you don't catch it in a variable, it's thrown on the floor. Same story for substring, trim, replace, and every other String method.

05

This should store 12 as a positive distance.

int diff = -12;
int distance = Math.abs;
Fix 
int distance = Math.abs(diff);

A method call always needs parentheses and whatever it's supposed to work on. Math.abs on its own is just a name with nothing attached, not a value. The parentheses are what actually run the thing.

06

This should print the first five characters, impor. It prints mpor instead.

String word = "important";
System.out.println(word.substring(1, 5));
Fix 
System.out.println(word.substring(0, 5));

Indexes start at 0, not 1, so starting at 1 skips the i. Sanity check as you go: the number of characters you get back is the second number minus the first. (1, 5) gives you 4 characters, (0, 5) gives you 5.

PART 3

Write it yourself

Short ones. Talk me through your thinking as you go, and it's fine if the syntax isn't perfect.

01

A notebook costs $12.75 and you're buying 3 of them. Declare the variables you need, work out the total, and print a sentence like 3 items cost $38.25.

One way 
double price = 12.75;
int quantity = 3;
double total = price * quantity;

System.out.println(quantity + " items cost $" + total);

Notice that price * quantity mixes a double with an int. Java quietly promotes the int, so the result is a double and you keep the cents. This is the one place mixing types works in your favor.

02

Given String fullName = "Lilah Martinez"; print just the first name.

The quick way 
System.out.println(fullName.substring(0, 5));
The better way 
int space = fullName.indexOf(" ");
System.out.println(fullName.substring(0, space));

Both print Lilah, but the first only works for a five-letter name. The second finds where the space actually is and stops right before it, so it works for any name you feed it. On the AP exam, the version that doesn't hardcode numbers is the one they're after.

03

You have two test scores, 88 and 93. Print the average as a decimal, not a whole number.

One way 
int first = 88;
int second = 93;
double average = (first + second) / 2.0;

System.out.println("Average: " + average);

The 2.0 is doing all the work here. Divide by plain 2 and you get 90 instead of 90.5, because both sides would be ints. The parentheses matter too, they make the addition happen before the division.

04

Given String word = "banana"; print how many characters it has, then print its last character.

One way 
String word = "banana";

System.out.println(word.length());
System.out.println(word.substring(word.length() - 1));

Six characters, last one is a. The last index is always length() - 1, because counting starts at 0 while length() starts at 1. That off-by-one is going to follow you all year, so it's worth getting comfortable with now. Also, substring with only one number means "go from here to the end."

PART 4

Seven things worth knowing

None of this is complicated. It's just the stuff that costs people points over and over.

01 Two whole numbers in, one whole number out

Any time both sides of a division are integers, Java throws away the remainder. 7 / 2 is 3. 1 / 2 is 0. To get decimals, make one side a decimal: 7.0 / 2 or (double) a / b.

This single rule causes more wrong answers in Unit 1 than everything else combined, so when a question involves division, check the types before you do the math.

02 Casting chops, Math.round rounds

(int) 9.99 is 9, not 10. If you want real rounding, go through Math.round first: (int) Math.round(9.99).

The extra (int) in front looks redundant but isn't. Math.round hands back a wider number type, so you need the cast to fit it into an int.

03 Strings count from zero and substring stops early

In "computer", the c sits at index 0 and the last character sits at index length() - 1. substring(2, 5) gives you indexes 2, 3, and 4, never 5.

Quick check you can do in your head: the result is always as long as the second number minus the first.

04 A String method never changes the original

Strings are read-only once they exist. name.toUpperCase() doesn't touch name, it returns a new String. You have to catch it: name = name.toUpperCase();

If a line calls a String method and doesn't assign the result to anything, that line does nothing at all. Worth scanning for whenever code "isn't updating."

05 Dot on a class vs. dot on an object

Math.abs(-4) puts the dot after a class name. word.length() puts it after a variable holding an object. Both are method calls, but they're different kinds.

The rule of thumb: if you had to build the thing before you could use it, you call methods on the thing. Math is a toolbox you never build a copy of, so you call methods straight on the name.

06 == and .equals() ask different questions

For int and double, == is exactly right. For Strings it asks "are these literally the same object," which is a different question from "do they say the same thing."

Rule you can follow without thinking: numbers get ==, text gets .equals().

07 Read code like a machine, not like a sentence

When a question has you stuck, stop reading it as a whole and trace it one line at a time. Write each variable in the margin and cross out the old value every time it changes.

Most Unit 1 multiple choice isn't testing whether you're clever, it's testing whether you'll actually do that instead of skimming. Slow tracing beats fast reading every time.
