Start here

Rebuild the features that survived testing, in one pass.

This is the same combined loop you know, building the five features that earned their place: Elo, surface Elo, head-to-head, rest, and experience. Form and serve stats are left out, they were tested and did not help.

import pandas as pd, numpy as np, joblib, json
from collections import defaultdict
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

df = pd.read_csv("atp_2000_2024_model_ready.csv", low_memory=False)
df["tourney_date"] = pd.to_datetime(df["tourney_date"])
df = df.sort_values(["tourney_date", "match_num"]).reset_index(drop=True)
is_A = df["winner_is_A"].values.astype(bool); cut = int(len(df) * 0.8)
def dynamic_k(n): return 250 / ((n + 5) ** 0.4)

elo=defaultdict(lambda:1500.0); games=defaultdict(int)
selo=defaultdict(lambda:1500.0); sgames=defaultdict(int)
h2h=defaultdict(int); last_date={}; played=defaultdict(int)
ew=np.zeros(len(df)); el=np.zeros(len(df)); sew=np.zeros(len(df)); sel=np.zeros(len(df))
hw=np.zeros(len(df)); rw=np.zeros(len(df)); rl=np.zeros(len(df)); xw=np.zeros(len(df)); xl=np.zeros(len(df))
for i,row in enumerate(df.itertuples(index=False)):
    w,l,s,d=row.winner_id,row.loser_id,row.surface,row.tourney_date
    a,b=elo[w],elo[l]; ew[i]=a; el[i]=b
    sa,sb=selo[(w,s)],selo[(l,s)]; sew[i]=sa; sel[i]=sb
    hw[i]=h2h[(w,l)]-h2h[(l,w)]
    rw[i]=(d-last_date[w]).days if w in last_date else 30
    rl[i]=(d-last_date[l]).days if l in last_date else 30
    xw[i]=played[w]; xl[i]=played[l]
    e=1/(1+10**((b-a)/400)); elo[w]=a+dynamic_k(games[w])*(1-e); elo[l]=b-dynamic_k(games[l])*(1-e); games[w]+=1; games[l]+=1
    se=1/(1+10**((sb-sa)/400)); selo[(w,s)]=sa+dynamic_k(sgames[(w,s)])*(1-se); selo[(l,s)]=sb-dynamic_k(sgames[(l,s)])*(1-se); sgames[(w,s)]+=1; sgames[(l,s)]+=1
    h2h[(w,l)]+=1; last_date[w]=d; last_date[l]=d; played[w]+=1; played[l]+=1

df["elo_diff"]=np.where(is_A,ew-el,el-ew); df["surface_elo_diff"]=np.where(is_A,sew-sel,sel-sew)
df["h2h_diff"]=np.where(is_A,hw,-hw); df["rest_diff"]=np.where(is_A,rw-rl,rl-rw); df["exp_diff"]=np.where(is_A,xw-xl,xl-xw)

baseline_acc = accuracy_score(df.iloc[cut:]["target"], (df.iloc[cut:]["rank_diff"] < 0).astype(int))
print("features rebuilt. baseline:", round(baseline_acc, 3))

Everything is in place. Now finish the job.

Feature selection

Choosing the final feature set based on evidence, not on what sounds good.

The principle. You built seven features over this chapter. Two of them, recent form and serve stats, were tested and did not improve the model, so they do not go in the final version. Deciding what stays based on measured value is called feature selection, and it is a core skill. A model with fewer, well-chosen features is simpler, faster, and easier to explain, and it usually generalizes better than one stuffed with everything you could think of.

Cell · the final feature set

FEATURES = ["elo_diff", "surface_elo_diff", "h2h_diff", "rest_diff", "exp_diff"]

train, test = df.iloc[:cut], df.iloc[cut:]
final = LogisticRegression(max_iter=1000).fit(train[FEATURES], train["target"])
final_acc = accuracy_score(test["target"], final.predict(test[FEATURES]))
print("baseline:", round(baseline_acc, 3), " final model:", round(final_acc, 3))

Baseline 0.637, final model about 0.650. Roughly a 1.3-point gain over baseline, built entirely from engineered features.

Example answer

Feature selection means keeping only the features that measurably improve the model and dropping the ones that do not. A smaller set is simpler to explain, faster to run, and less likely to overfit, because unhelpful or redundant features mostly add noise. Choosing features by tested value rather than by what sounds important produces a cleaner, more trustworthy model.

Retrain all seven models

Bring back the v1 lineup and run it on the engineered features, closing the loop with your original study.

Distance and gradient models need scaled features, so scale once and reuse.

from sklearn.preprocessing import StandardScaler
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import LinearSVC
from sklearn.neural_network import MLPClassifier

X_tr, y_tr = train[FEATURES], train["target"]
X_te, y_te = test[FEATURES],  test["target"]
scaler = StandardScaler().fit(X_tr)
Xs_tr, Xs_te = scaler.transform(X_tr), scaler.transform(X_te)

models = {
    "logistic regression": (LogisticRegression(max_iter=1000), False),
    "decision tree":  (DecisionTreeClassifier(max_depth=5, random_state=42), False),
    "random forest":  (RandomForestClassifier(n_estimators=200, max_depth=8, random_state=42, n_jobs=-1), False),
    "gradient boosting": (GradientBoostingClassifier(max_depth=3, random_state=42), False),
    "KNN":        (KNeighborsClassifier(n_neighbors=25), True),
    "linear SVM": (LinearSVC(max_iter=5000), True),
    "neural net": (MLPClassifier(hidden_layer_sizes=(16, 8), max_iter=300, random_state=42), True),
}
rows = []
for name, (m, needs_scale) in models.items():
    a = Xs_tr if needs_scale else X_tr
    b = Xs_te if needs_scale else X_te
    m.fit(a, y_tr)
    rows.append((name, round(accuracy_score(y_te, m.predict(b)), 4)))

pd.DataFrame(rows, columns=["model", "accuracy"]).sort_values("accuracy", ascending=False)

Stability and importance

Confirm the number is not a fluke, then see which features did the work.

Cross-validation: is 0.65 stable?

from sklearn.model_selection import cross_val_score
cv = cross_val_score(LogisticRegression(max_iter=1000), df[FEATURES], df["target"], cv=5)
print("folds:", [round(x, 3) for x in cv], " mean:", round(cv.mean(), 3))

The folds land in the mid-0.60s (mean around 0.66), confirming the result is stable and real, not an artifact of one particular split.

Ship v2 to the live app

The satisfying finish: upgrade the public site to a "pick two players, pick a surface" predictor powered by Elo.

The plan. Save a compact model that uses just elo_diff and surface_elo_diff (almost as accurate, and easy to run from a lookup), plus a table of every player's current Elo and per-surface Elo. Then the app lets someone pick two players and a surface, looks up their ratings, and predicts. This is the interactive demo you sketched at the very start, now real.

Cell · save the app model and the player rating lookup

# compact model: two features we can compute from a lookup
app_model = LogisticRegression(max_iter=1000).fit(train[["elo_diff", "surface_elo_diff"]], train["target"])
joblib.dump(app_model, "app_model.joblib")

# current ratings for every player with enough matches
names = pd.concat([
    df[["winner_id","winner_name"]].rename(columns={"winner_id":"id","winner_name":"name"}),
    df[["loser_id","loser_name"]].rename(columns={"loser_id":"id","loser_name":"name"}),
]).drop_duplicates("id").set_index("id")["name"]

lookup = {}
for pid in games:
    if games[pid] >= 30:                      # enough history to be meaningful
        lookup[names[pid]] = {
            "elo":   round(elo[pid], 1),
            "Hard":  round(selo[(pid, "Hard")], 1),
            "Clay":  round(selo[(pid, "Clay")], 1),
            "Grass": round(selo[(pid, "Grass")], 1),
        }
json.dump(lookup, open("player_elo.json", "w"))
print("saved app_model.joblib and", len(lookup), "players")

About 600 players saved. The model uses two features and predicts at ~0.646, nearly the full model, from a simple lookup.

app.py · the upgraded Streamlit app

import streamlit as st
import joblib, json

model = joblib.load("app_model.joblib")
players = json.load(open("player_elo.json"))
names = sorted(players)

st.title("ATP Match Predictor (v2, Elo-powered)")
st.write("Pick two players and a surface. The model uses their Elo ratings to predict the winner.")

a = st.selectbox("Player A", names, index=names.index("Novak Djokovic"))
b = st.selectbox("Player B", names, index=names.index("Rafael Nadal"))
surface = st.selectbox("Surface", ["Hard", "Clay", "Grass"])

pa, pb = players[a], players[b]
elo_diff = pa["elo"] - pb["elo"]
surface_elo_diff = pa[surface] - pb[surface]
prob_a = model.predict_proba([[elo_diff, surface_elo_diff]])[0][1]

st.metric(f"{a} win probability", f"{prob_a*100:.0f}%")
st.progress(prob_a)
st.caption(f"{a} favored" if prob_a > 0.5 else f"{b} favored")

6.Explain the leakage rule and give one example of a feature that would have leaked if built wrong. write it

Example answer

The leakage rule is that a feature may only use information available before the match, which we enforced by reading each value before updating it with the result. For example, using this match's aces as a serve feature would leak, because those aces are produced during the match we are predicting; only career serve stats coming into the match are fair.

7.Why does the model top out in the mid-60s no matter what you do? write it

Example answer

Because most of what is predictable about a tennis match comes from the skill gap, which Elo already captures well, and beyond that the outcome depends on upsets and day-to-day variation that no pre-match feature can foresee. Once skill is accounted for, the remaining uncertainty is largely irreducible, so accuracy plateaus in the mid-60s, the same ceiling professional betting markets reach.
