This single loop rebuilds overall Elo, surface Elo, and experience together (all the established features), so you have them ready.

import pandas as pd
import numpy as np
from collections import defaultdict, deque
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

df = pd.read_csv("atp_2000_2024_model_ready.csv", low_memory=False)
df["tourney_date"] = pd.to_datetime(df["tourney_date"])
df = df.sort_values(["tourney_date", "match_num"]).reset_index(drop=True)
is_A = df["winner_is_A"].values.astype(bool)
cut = int(len(df) * 0.8)

def dynamic_k(n):
    return 250 / ((n + 5) ** 0.4)

elo = defaultdict(lambda: 1500.0);         games = defaultdict(int)
surface_elo = defaultdict(lambda: 1500.0); surface_games = defaultdict(int)
played = defaultdict(int)
elo_w = np.zeros(len(df)); elo_l = np.zeros(len(df))
selo_w = np.zeros(len(df)); selo_l = np.zeros(len(df))
exp_w = np.zeros(len(df)); exp_l = np.zeros(len(df))

for i, row in enumerate(df.itertuples(index=False)):
    w, l, s = row.winner_id, row.loser_id, row.surface
    a, b = elo[w], elo[l]
    elo_w[i] = a; elo_l[i] = b
    sa, sb = surface_elo[(w, s)], surface_elo[(l, s)]
    selo_w[i] = sa; selo_l[i] = sb
    exp_w[i] = played[w]; exp_l[i] = played[l]
    # updates
    e = 1 / (1 + 10 ** ((b - a) / 400))
    elo[w] = a + dynamic_k(games[w]) * (1 - e); elo[l] = b - dynamic_k(games[l]) * (1 - e)
    games[w] += 1; games[l] += 1
    se = 1 / (1 + 10 ** ((sb - sa) / 400))
    surface_elo[(w, s)] = sa + dynamic_k(surface_games[(w, s)]) * (1 - se)
    surface_elo[(l, s)] = sb - dynamic_k(surface_games[(l, s)]) * (1 - se)
    surface_games[(w, s)] += 1; surface_games[(l, s)] += 1
    played[w] += 1; played[l] += 1

df["elo_diff"] = np.where(is_A, elo_w - elo_l, elo_l - elo_w)
df["surface_elo_diff"] = np.where(is_A, selo_w - selo_l, selo_l - selo_w)
df["exp_diff"] = np.where(is_A, exp_w - exp_l, exp_l - exp_w)

baseline_acc = accuracy_score(df.iloc[cut:]["target"], (df.iloc[cut:]["rank_diff"] < 0).astype(int))
print("baseline:", round(baseline_acc, 3))

Baseline near 0.637, and your three features are back. Now add matchup and fatigue.

Head-to-head

Some players just match up badly against particular opponents. The prior record between two players captures that.

The idea. Rankings and Elo say who is better overall, but tennis has matchup effects: a lefty's spin that troubles one opponent, a game style another player cannot solve. The head-to-head record (how many times A has beaten B before) captures that pairwise history that a single rating cannot.

The new idea: a key made of two players

Surface Elo used a (player, surface) key. Head-to-head uses an ordered pair of players: h2h[(winner, loser)] counts how many times the first beat the second. The feature is A's prior wins over B minus B's prior wins over A.

Cell · head-to-head

h2h = defaultdict(int)                       # h2h[(x, y)] = times x has beaten y
h2h_w = np.zeros(len(df))                     # winner's prior edge over loser

for i, row in enumerate(df.itertuples(index=False)):
    w, l = row.winner_id, row.loser_id
    # READ: prior record BEFORE this match (0 if they have never met)
    h2h_w[i] = h2h[(w, l)] - h2h[(l, w)]
    # UPDATE: the winner now leads by one more
    h2h[(w, l)] += 1

df["h2h_diff"] = np.where(is_A, h2h_w, -h2h_w)
The never-met case handles itself. If A and B have never played, both h2h[(w,l)] and h2h[(l,w)] are 0 (that is what defaultdict(int) returns), so h2h_diff is 0, a neutral "no history." That is exactly what you want, and it happens for free.

Rest and fatigue

Days since a player's last match. A tired player who just played a five-setter may be at a disadvantage.

Rest is simply the number of days between a player's previous match and this one. You get it by remembering each player's last match date and subtracting.

Cell · rest (days since last match)

last_date = {}                               # each player's most recent match date
rest_w = np.zeros(len(df)); rest_l = np.zeros(len(df))

for i, row in enumerate(df.itertuples(index=False)):
    w, l, d = row.winner_id, row.loser_id, row.tourney_date
    # READ: days since last match (default 30 if this is their first match)
    rest_w[i] = (d - last_date[w]).days if w in last_date else 30
    rest_l[i] = (d - last_date[l]).days if l in last_date else 30
    # UPDATE: record this match as their latest
    last_date[w] = d; last_date[l] = d

df["rest_diff"] = np.where(is_A, rest_w - rest_l, rest_l - rest_w)
The first-match case. A player appearing for the first time has no previous match, so w in last_date is false and we default their rest to 30 days, a typical gap. Without that default, subtracting from a missing date would crash. Choosing a sensible default is the heart of defensive coding, which is the next tab.

2.In a markdown cell, give one reason more rest could help a player and one reason it could hurt. write it

Example answer

More rest can help because the player is recovered and fresh rather than tired from a recent long match, so they have more energy. Edge cases and defensive coding

The real skill of history features: handling the messy cases without crashing or lying.

Why this matters. Real data is full of "what happens when...". If you do not decide, the code either crashes or silently produces a wrong number. Every history feature you build should answer: what is the value the very first time I see this player or pair? You have already hit three cases:
  • New player, no experience: count defaults to 0 (from defaultdict(int)).
  • Two players who never met: head-to-head defaults to 0, a neutral "no history."
  • A player's first match: rest defaults to 30 days, a typical gap, instead of crashing on a missing date.

The subtle one: is a big number an outlier, or real signal?

Your rest values reach into the thousands of days (injury comebacks). The instinct is to treat those as outliers and cap them, say at 60 days. But test before you assume. Compare capped rest to raw rest:

rest_w_cap = np.minimum(rest_w, 60)          # cap each value at 60 days
rest_l_cap = np.minimum(rest_l, 60)
df["rest_cap_diff"] = np.where(is_A, rest_w_cap - rest_l_cap, rest_l_cap - rest_w_cap)

train, test = df.iloc[:cut], df.iloc[cut:]
def acc(cols):
    m = LogisticRegression(max_iter=1000).fit(train[cols], train["target"])
    return round(accuracy_score(test["target"], m.predict(test[cols])), 4)

base_cols = ["elo_diff", "surface_elo_diff"]
print("+ rest (raw):   ", acc(base_cols + ["rest_diff"]))
print("+ rest (capped):", acc(base_cols + ["rest_cap_diff"]))

The capped version scores lower (about 0.6465 vs 0.6479 raw). Capping hurt.

The lesson. Those huge rest values were not noise, they were signal: a player returning after a very long layoff really is more likely to lose, and capping threw that information away. This is one of the most important habits in the whole craft: do not clean data on instinct, test whether the "cleaning" actually helps. Here, keeping the raw values is the right call, and only a measurement told you that.
A defensive-coding checklist for any future feature:
  • What is the value the first time I see this player or pair? (pick a sensible default)
  • Could a lookup crash on missing data? (guard it, like if w in last_date)
  • Are there extreme values? (look at min and max, then test whether handling them helps)
